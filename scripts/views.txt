# Views `make screenshot` renders, one "<name> <url>" line each. Blank lines and # are
# skipped. Renders land in captures/ui/<name>.png, which is gitignored.
#
# This file is an INPUT and is tracked. It used to live at captures/views.txt, inside the
# directory .gitignore excludes wholesale — so the list of which views are worth looking at
# could not be committed, and the next clone would have started with none.
#
# The URLs assume `make dev` is already serving. It blocks, so background it first.
#
# WHAT THESE RENDERS SHOW DEPENDS ON WHETHER `make server` IS UP, and that is worth knowing
# before comparing one against docs/design-refs/locked.html. Every view below except the
# gallery reads the capture server: with it down they draw their failure panel, which is a
# real screen and the wrong one to judge a layout by. With it up and an empty store they draw
# their empty state. Neither shows a populated screen, and no run in this repo has ever
# produced one — see docs/specs/capture-app.md's STATUS section.

# The hash route is load-bearing, not decoration. The gallery answered at '/' while it was
# the whole app at step 6; step 7a mounted the capture screen there. Dropping the '#/gallery'
# renders the capture screen into captures/ui/pull-confirm.png — a screenshot that is named
# after one view and shows another, which is worse than no screenshot, because the loop
# docs/DESIGN.md calls mandatory is a human comparing this render against the reference.
pull-confirm  http://localhost:5173/#/gallery

# Step 7a's two screens — now one. The capture screen renders without a camera in a headless
# render — that is not a defect to work around, it is the first thing a person sees before
# granting permission, and it is worth looking at deliberately rather than only ever seeing
# the happy path. The layout underneath it renders either way.
#
# `pull-preview http://localhost:5173/#/pull` stood here until D31 merged that route into
# #/inventory. The walk it rendered did not go anywhere — it is the browse mode of the
# `inventory` line below, which is why this list lost a view without losing a render.
capture       http://localhost:5173/#/

# 7b's three screens, routed 2026-08-13. The review queue is the one to actually look at:
# docs/DESIGN.md specifies its shape in more detail than any other screen in the product and
# it held its first real cards on 2026-08-22: Gate B's 16 entries, every one answered here.
# The render still earns its place — all 16 were one reason code and all were parked, so
# most of what docs/DESIGN.md specifies has still only ever been drawn.
review        http://localhost:5173/#/review
inventory     http://localhost:5173/#/inventory

# The pipeline, on its own route since 2026-08-29 (D39). Worth its own render for the reason
# every other line here has one: it is a screen a human looks at, and with the capture server
# down it draws its own refusal rather than the box picker — which is a real state and the
# wrong one to judge the layout by. It draws no stored capture photo at all, so the `views
# exposure` question the other owner routes raise does not arise here.
runs          http://localhost:5173/#/runs

# Hand-pricing, on its own route since 2026-08-30 (D49). Rendered with no `?run=` parameter,
# so what a person sees here is the run picker — the state the screen opens in when it is
# reached by its chord rather than by the link from `#/runs`, and the one whose chrome the
# page-chrome numbers govern. It draws no stored capture photo in that state; the photo panel
# is opened per row, on demand, and cannot be in a render taken with nothing selected. So the
# `views exposure` question the other owner routes raise does not arise here either.
pricing       http://localhost:5173/#/pricing

fulfillment   http://localhost:5173/#/fulfillment
