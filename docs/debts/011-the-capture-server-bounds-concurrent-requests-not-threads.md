## 11 — A writer holding the store lock holds a request slot, and the bounds are proven on an empty store

`server/capture_server.py` serves on `class CaptureServer(ThreadingHTTPServer)` with `request_queue_size = 128`, which bounds the accept backlog and not threads. `CaptureHandler.timeout = 15` reaps a thread parked on a socket read. `REQUEST_SLOTS = 4` caps how many requests execute, through a semaphore around `_dispatch` and a `ThreadPoolExecutor` in `CaptureServer.process_request`. `PHOTO_SLOTS = 4` gives `GET /photo/` and `/assets/` their own pool and refusal (`photo_busy`), because they touch no store and no lock. Every response sends `Connection: close` from `end_headers`, which every response reaches by construction, so a pool worker lives for one request and idle keep-alive connections cannot starve it. Without that header four idle connections hold all four workers and `make harness` hangs.

**The gap.** A request that waits on the store lock holds its slot for up to `files.LOCK_TIMEOUT_SECONDS` (30s). Four such writers stall every non-photo route, `/status` included. T7's `check_request_slots`, `check_photo_lane` and `check_photo_lane_threads_and_faults` prove the mechanism on an empty store. Nothing proves the bound holds a real store against a fleet of clients. The collapse (969 threads under 80 browsers, a probe answered in 18s at 150 connections) was measured before the pool, and the browser suite is sealed off this server (`app/tests/shell.ts:sealEveryTest`), so `make design-check` no longer loads it.

**Outcome at risk.** The owner's live capture server wedges or is killed mid-write. Do not restart it to fix a wedge: `make launch-agent` keeps that process alive, and a kill with a write in flight is what loses data. Run the full suite once, at the end. Navigate a hand-driven browser page to `about:blank` before closing it, so no handler writes to a dead socket.

**Closes when.** A lane for the routes that touch no lock (`/status`), or a run on a scratch store with four writers parked shows every other route still answers.
