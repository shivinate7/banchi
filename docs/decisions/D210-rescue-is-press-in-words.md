## D210 — Rescue is a press, reported in words

**`banchi rescue` (D145) is reached from a press, and its report is worded and never shown verbatim.** A tooltip that names a command in backticks is the "route with no control" defect in a smaller shape. The route is `POST /pipeline/runs/<name>/rescue`, mirroring `do_queue_refresh`: free, preview by default, `write` gated. It is dispatched ahead of `_RUN_STEP_RE` (`_RUN_RESCUE_RE`). The client is `rescueRun` in `app/src/server.ts`, and the control is on `RunPanel.tsx`'s header, shown only where `detail.box_former` is true. `RunRescue.tsx` is the sheet, and the `#/pricing` tooltip names no command.

- **Raw machine text is never visible on the front end, not even behind a disclosure** (stdout, JSON, a CLI string, a path). This route is the deliberate exception to D33's stdout-verbatim habit. Rescue's report carries backticked `banchi` invocations and names `CLAUDE.md`, the class `no mechanism on screen` (D196) refuses. `do_run_rescue` returns a small `RescueResult` (`ok`, `wrote`, a `reason` code, `counts`, `destination`, `already_rescued`, `new_run`) and writes the raw text to `runs/<name>/logs/rescue-<stamp>.log`. The sheet composes every sentence from those typed fields and translates `reason` through `REASON_COPY`.
- **Never parse the CLI's own English prose.** The first build recovered `reason` with substring matches over sentences a human reads, and only one of six reasons was exercised by anything real, so rewording a sentence silently returned the wrong code with every check green. The cause was that the command had no machine-readable output. `cli/cmd_rescue.py --json` (off by default, so the terminal report is unchanged) prints one compact JSON line (`_report_line`) before every return and raise, built from the same variables as the prose. `_extract_rescue_report` scans stdout from the end for the first JSON object carrying `reason` and `counts`.
- **The write is a press and not a route change (D118).** The sheet opens over the run's header, and a successful write's receipt links to the new run by name (`onOpenRun`). The source run is never edited. Reopening the sheet re-previews, since the shelf may have moved.
- **Guarded.** `check_rescue_json_reasons` pins all six reason codes (`not_stranded`, `none_on_shelf`, `spread_across_boxes`, `digest_ambiguous_on_disk`, `digest_twice_in_run`, `no_identifications`) against the real condition through the real CLI (`entry.main`). `check_rescue_route` asserts no `console` key reaches the response and the log lands on disk. Four cases in `app/tests/run-panel.spec.ts` cover the visibility gate, preview before Apply, the receipt and way back, and a refusal drawing a sentence, and assert the sheet's text never contains `banchi`, a decision citation or a log path. `no mechanism on screen` carries `_CLI_INVOCATION_RE` for a backticked `banchi …`, pinned by the `CliInvocation.tsx` fixture.
