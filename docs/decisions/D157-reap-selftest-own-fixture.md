# D157 — Reap self-test names its own fixture

**The reap self-test's fixture carries a per-run name.** The process table is the one thing a run cannot have its own of. `scripts/reap.py --hook` resolves a kill's real targets with `pgrep -f` across the whole machine (D127). So a fixture that spawns a fixed-name script (`mine.py`) collides with any second live one in another checkout. The guard is right to refuse in that case.

Two things can start a second one. A concurrent `make check` from another worktree of this clone is one cause. A `time.sleep(300)` leaked by a run that never reached its `EXIT` trap is the other. `spawn` uses `start_new_session=True`, so a `killpg` never reaches the suite. The SIGINT that stops a `make check` therefore never reaches the children either. A `-9` runs no trap.

- **A lock is the wrong answer.** D122's machine-wide refusing lock is for a target deliberately off the commit path. `make reap-selftest` runs in `make check`. A lock would make one tree's suite block on another's commit. A process name costs nothing, so the fixture is made unable to collide. Every script is named `<role>-<mktemp suffix>-<pid>.py`, unique among live temp directories. The pid covers a suffix that `mktemp` later freed.
- **The port is fixed the same way.** Probing 53900 to 53960 for a port that nothing answers is a reading, not a reservation. Two runs probing together both find one free. The listener binds port 0 and reports the port the kernel gave it.
- **The arm reproduces the collision.** A rival fixture, built by the same naming rule, keeps running. Meanwhile this run asks the guard to kill its own process. A hand-named decoy would not survive the mutation that the arm exists to catch. The arm has two cases. If `pgrep` finds nothing, a passing case is worth nothing. The rival's own name is judged from this checkout and must still be refused. Reverting the naming rule turns exactly that arm red.
- **A leftover is harmless, but it is not gone.** The tag shows that this run's command cannot resolve a survivor. Each sleeper watches its own script file. If that file is deleted, the sleeper exits. The trap first waits for the sleepers to exit, and then it sends `-9`. A run killed with `-9` deletes nothing. Its sleepers stand until their own deadline, which only the tag covers.
- **`pgrep -fc` is not a count on BSD.** It returns 0 and reads as "no orphans". Count with `pgrep -f ... | wc -l`.
