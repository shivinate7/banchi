## D232 — Lossless cleanup runs without a word

**The lossless half of the cleanup needs no word, and the daily schedule is the backstop for the events that miss.** **An unattended sweep may also remove a worktree, but only one that claude-settings' sweep judges dead: its daily `sweep.py --confirm` is that unattended sweep.** It keeps a tree with uncommitted work, a live session, a lock or a process in it. The `--branches` mode below still touches branches and nothing else. Tier 2 was three acts under one word, and they are not alike. Removing a worktree can cost uncommitted work the sweep failed to see. Stopping a loose process can cost a run somebody wanted. Cutting a branch costs nothing when main is a descendant of every commit on it (`reapable_branches` puts a branch in its `cut` list only then), since `git branch -D` removes a label and every object stays reachable from main. Holding a lossless act behind the same word as a lossy one left merged branches with nobody to press it.

- **`janitor.py --branches` runs unattended, and it is branches and nothing else.** It removes no tree and stops no process, and the self-test asserts that against an idle worktree the full sweep would have taken. It fails closed on a layout it cannot read: `held` comes from `git worktree list`, and with no trees every branch would be eligible, including one somebody stands on, so that state is refused. A held branch is never considered, which is stronger than surviving. Git refuses to delete a branch checked out in a linked worktree by itself, so survival is not evidence the protection ran. The self-test reads silence about that branch.
- **The hook runs it at the moment a branch becomes cuttable.** `scripts/session-teardown.sh` runs on `SessionEnd` and `WorktreeRemove` and gains the branch cut after teardown and tier 1. A tree going is what releases its branch from `held`. The mode is idempotent, so a hook can run it on every session end.
- **The schedule is the backstop, since both events miss.** `SessionEnd` is unreliable at app quit and machine sleep, and `WorktreeRemove` fires only when somebody removes a tree, so a tree abandoned by a dead session is removed by nobody. The daily launch agent is claude-settings' (`com.claude-settings.janitor.daily-sweep`), and `make janitor-agent` is retired: it prints how to drop the old agent and installs nothing. It uses a calendar interval and never `KeepAlive`, since it is a sweep that ends, and launchd runs a missed job at the next wake.
- **The log is the receipt.** An unattended deletion writes the account claude-settings' sweep prints to its own launchd log. A deletion nobody watched and nobody can read afterwards is what this repo does not do.
- **What no autonomy touches:** branches carrying commits that exist only on this disk are kept, since they hold the only copy.
- **It is on no gating hook and in no check** (D18, as `icloud-sweep`): they are the only targets that can delete a file, and a launch agent writes to `~/Library`. The self-test gates and writes only in a temp directory.
- **The permission was the owner's narrow word ("Both halves", after four options),** recorded because it moves a gate. A blanket earlier word was not approval of the widest option (D228's defect, one lane over).
