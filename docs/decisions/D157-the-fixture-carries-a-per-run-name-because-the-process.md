## D157 — The reap self-test names its own fixture

**The reap self-test's fixture carries a per-run name, because the process table is the one thing a run cannot have its own of.** `scripts/reap.py --hook` resolves a kill's real targets with `pgrep -f` across the whole machine (D127), so a fixture spawning a fixed-name script (`mine.py`) collides with any second live one in another checkout, and the guard is correctly right to refuse. Two things put a second one there: a concurrent `make check` from another of this clone's worktrees, and a `time.sleep(300)` leaked by a run that never reached its `EXIT` trap. `spawn` uses `start_new_session=True` so a `killpg` never reaches the suite, so the SIGINT that stops a `make check` never reaches the children either, and a `-9` runs no trap.

- **A lock is the wrong answer here.** D122's machine-wide refusing lock is for a target deliberately off the commit path. `make reap-selftest` is in `make check`, so a lock would make one tree's suite block on another's commit. A process name costs nothing, so the fixture is made unable to collide: every script is `<role>-<mktemp suffix>-<pid>.py`, unique among live temp directories, with the pid covering a suffix `mktemp` later freed.
- **The port is fixed the same way.** Probing 53900 to 53960 for a port nothing answers is a reading and not a reservation, since two runs probing together both find one free. The listener binds port 0 and reports what the kernel gave it.
- **The arm reproduces the collision.** A rival fixture built by the same naming rule stays running while this run asks the guard to kill its own process. A hand-named decoy would survive the mutation the arm exists to catch. It is two cases, because one that passes when `pgrep` finds nothing is worth nothing: the rival's own name is judged from this checkout and must still be refused. Reverting the naming rule turns exactly that arm red.
- **A leftover is harmless, not absent.** The tag means a survivor cannot be resolved by this run's command. Each sleeper watches its own script file and exits when it is deleted, and the trap waits for them to be gone before sending `-9`. A run killed with `-9` deletes nothing, and its sleepers stand until their own deadline, which only the tag covers.
- **`pgrep -fc` is not a count on BSD.** It returns 0 and reads as "no orphans". Count with `pgrep -f ... | wc -l`.
