## D188 — Join reads the store without a run

**`pkmnscan join --keys 3/1,3/2 --export <file>` resolves cards straight off the store's own `Card` records, with no `identify` run, no `identifications.json` and no frozen snapshot to reconcile.** A run directory still works as before (`pkmnscan join <run-dir> --export <file>`). Naming both, or neither, is refused with a named remedy. This is D180's move on the read side: a run is an immutable input, but `join` could not be re-run once its directory was gone, though every fact it needs sits on the live `Card` row.

- **Two loaders, both producing a `Resolved`.** `resolve.load(run, exports)` is the replay path: it reads `run.read_identifications()`, then `realign` (D36) and `refuse_reallocated`. `resolve.load_from_store(run, keys, exports)` builds the same `{"cards": {...}}` shape from `store_payload(keys, inventory)` off the current store and hands it to the shared tail, `_resolve`. It runs neither `realign` nor `refuse_reallocated`, because a card's position is read at that instant and is correct by construction. `store_payload` never silently drops a card the store has no record of, so a bad `--keys` entry is refused by name. A never-identified but positioned card routes to the main review queue as an `identify` failure would.
- **`run` still names where this join's output lands.** `cli/cmd_join.py` creates it with `runs.create(...)` only once the selection and export are known good, so a refusing request leaves no directory. It carries a `selection` block in its manifest and never `identifications.json`. A `--dry-run` creates no run directory at all (an in-memory `Run` is never saved).
- **Field completeness is settled by a diff.** `harness.tests.t7.cli_identify.check_store_backed_join` writes three cards through the ordinary writers (`record_capture`, `record_identification`) and into a run's `identifications.json`. It compares every `SkuMatch` from the two loaders by dataclass equality, not a hand-picked field list, and the queue entries the ambiguous card earns, candidates included. It asserts `realigned`, `departed` and `unverified_boxes` empty, which shows the replay branch never ran. A fixture that forgot to mirror `metadata_finish` onto the store row was the shape of bug this catches and set comparison would not.
- **`submitted` is in every run manifest:** the sorted position keys actually sent to the model, after the claim negotiation narrows them (D174). `selection` is the query, `scope` the derived drawer, `submitted` what was billed. `cli/runs.py:Run.submitted` is the cheap reader, and `cmd_identify:_run_keys_of` (the `--run <name>` term) reads it first, so it need not open a large `identifications.json`.
- **`rescue` refuses a store-backed join's directory by name.** It repairs a frozen run's stale positions (D36), and a store-backed join can never be stranded in that sense. `rescue` keeps refusing a run whose cards land across more than one current box, since `Run.scope` and D145's `bid` are singular.
- **Limits.** `emit` reads only frozen run directories, so a store-backed join can populate the review queue and seed `inventory/prices.json` but cannot itself produce the CSV to upload. The natural shape is the same two-loader branch in `cli/cmd_emit.py`. `join --keys` is the one selection term wired. `identify`'s fuller vocabulary (`--box`, `--state`, `--game`, `--since`, `--run`) is not, because `pipeline/selection.py` scans `Capture` objects off disk, and a store-only filter needs a second filter over `Card` rows or an adapter.

Reopen for `join --box 3` or `join --state identified` wanted directly, and for `emit` gaining the two loaders. `_phase` reads a store-backed join through D199.
