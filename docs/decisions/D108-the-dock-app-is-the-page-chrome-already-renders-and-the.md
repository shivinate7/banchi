## D108 — The dock app is an installed web page

**The dock app is Chrome's install of the page, made real by the manifest.** Nothing is wrapped or bundled, and the capture server stays a launch agent. Chrome's *Install page as app* writes a real bundle with its own dock icon and ⌘-Tab entry, its own window (`display-mode: standalone`) and a remembered size. The camera is unchanged, because the engine is unchanged. The rig has only been proven on Chromium, and the grant lives per origin in the profile. `app/src/useCamera.ts` asks for 3840x2160 with `deviceId: {exact}`. A host that settled on 1080p would pass the 1280x720 floor and be four times worse than the rig can produce, silently.

- **Rejected:** Safari's Add to Dock (WebKit: never rendered there, and the Cam Link's 4K under `getUserMedia` is unmeasured). Tauri (WebKit plus a Rust toolchain absent from this Mac, in a repo whose capture server must never need `make venv`). Electron (Chromium, but 150-250MB, a second build pipeline, and a wrapper tempted to own the server).
- **The dock app is a client and never a second supervisor.** A wrapper that started the capture server would repeat D138's measured defect: two supervisors, one serving and one supervising nothing, and a pidfile naming the wrong one. `make launch-agent` keeps `:8000` answering. With the supervisor down, the dock icon opens Chrome's error page, which is accepted.
- **The manifest is an install manifest.** Its URLs are relative (`.`, `icon-192.png`). Vite copies `app/public/` verbatim, so site-absolute URLs 404 at any base but `/`, as the published demo showed. `launch_handler: {client_mode: "focus-existing"}` makes a second dock press focus the open window (`navigate-existing` would send a mid-review press home). `id` decouples identity from `start_url`, and `scope` is explicit. `background_color` stays dark, since a manifest holds one value and `app/index.html` carries the two `theme-color` metas.
- **The icon follows the macOS grid.** `docs/specs/logo.md` section 17 locks 824pt of artwork on a 1024pt canvas, which is what Safari, Mail and Calculator measure (80.47% solid), where the mark filled 100%. The whole manifest set is inset, because Chrome builds the `.icns` by resizing it. `favicon.svg` is out of the icon list and stays the tab icon, and `icon-180.png` is full bleed because iOS masks it. Nothing redraws the mark: it is drawn smaller on a transparent canvas, and `make docs-audit`'s `mac icon grid` row reconciles `MAC_GRID` with section 17 and the manifest set with the generator. A dark dock icon is refused. Chrome writes a plain `.icns`, and section 12 rules the icon an object that does not invert. The drop shadow is unsettled, and section 17 names the sweep that would settle it.
- **The install URL is `http://localhost:8000`,** since the capture server serves the page and `:5173` belongs to `make dev`. A port is part of an origin, so a move resets the camera grant and every `localStorage` key once (D27). Move between shifts, since `banchi.session.captureId` is `sessionStorage` and a capture in flight can burn a position.

Reopen for a second person needing a signed install, for Chrome going away, or for a page needing something a browser withholds.
