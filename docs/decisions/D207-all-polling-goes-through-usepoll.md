## D207 — All polling goes through usePoll

**`app/src/usePoll.ts` is the one polling primitive.** It pauses while `document.hidden` and ticks at once when the tab is looked at again. It backs off the idle cadence on consecutive failures instead of hammering a server that went quiet. One module-level counter shared by every `usePoll` never lets more than `REQUEST_SLOTS` (4) requests be in flight against the capture server (DEBT11: less concurrency is strictly better on this rig). Five hand-rolled timers had none of this (the run list, an open run's detail, the submission claims panel, the sidebar's `/status` poll). The primitive was unfactored and not missing. So migrating all five is the proof, and their existing specs staying green verifies it. A new spec of the hook in isolation would only prove the hook works.

- **Every request feeds server presence.** The offline banner once learned the server was gone only from its own `/status` poll. So any other failing request left it up to 15 seconds stale. `server.ts:request()` is the one seam every call passes through (as `noteBoot` already uses). `noteReachable(ok)` fires on both the success and failure path, and only when the state changes. `onServerReachable` lets the shell subscribe. A failure the server still answers `/status` for (an origin refused at the CORS preflight, `origin_blocked`) reads as reachable, since the server is up.
- **The Orders live subscriber is deferred on measurement.** There is no cheap "anything new?" call. `order_transport.py:search_body` hardcodes ascending `sortBy` with no direction parameter. `totalOrders` sits still through a status change. It cancels out on a simultaneous add and remove. A poll would hold one of four slots for up to `TIMEOUT_S = 30`, and the transport has no throttle (D91). Fetch is one click, and a poller does not make an order ship sooner. Reopen when the owner finds pressing Fetch by hand bothersome for a week, or when `order_transport.py` gains a `since` or newest-first parameter. `usePoll` is not Orders-specific and takes a sixth caller.
