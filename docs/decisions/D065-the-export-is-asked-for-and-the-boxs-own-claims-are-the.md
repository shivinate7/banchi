## D65 — The export request names its own scope

**One press fetches the export and joins.** The request names a category and a set from the box's own claims (game, set hint), so the file is complete within that scope by construction. Name the scope and never judge a fetched file.

- **The endpoint is `POST /admin/pricing/downloadexportcsv`,** the Export Filtered CSV button's own request, captured off the wire. `DownloadMyExportCSV` ignores every parameter and serves the saved filter. Every body value is a string, and "all" is `["0"]`, never an empty list (`0` is the All Set Names row's own id). `MyInventory: false` (catalog, not the operator's listings) and `PrintingIds: ["0"]` (a number stocked in several finishes must arrive with all of them, or D3 rung 2 decides from whichever survived) are never negotiable.
- **The guard is positive.** `export_scope_incomplete` refuses when a set asked for is absent, because every card in it would queue as `no_catalog_row` from a fetch that reported success. No delta guard exists.
- **`CategoryId` is scalar,** so a mixed-game run fetches once per game. The request takes `game` and refuses `game_required` when a run holds more than one. `tcgplayer_category_id` sits beside `product_line` in `pipeline/games.py`. `getjsonfilters?categoryId=N` reads the vocabulary.
- **A hint resolves through one ladder in `pipeline/setnames.py`,** read by the fetch and the join: whole label, either colon side, a guarded prefix, then an abbreviation. Substring is not a rule (`Origins` is inside `Origins: Proving Grounds`). Resolution is set-wise and answers `None` on a tie, because pairwise `set_matches` handed back four `SV:` sets as a confident narrowing. `set_matches` survives only as the yes/no question for one pair (T3). `match_sets` keeps mapping a resolved name to the portal's id, and drops the `All Set Names` row before resolution.
- **An ambiguous hint widens the fetch to the whole category.** That is slower and always correct, and narrowing onto a set the box is not in is not.
- **An abbreviation is the hint's letters in order, anchored on the first,** run through the name minus its block code. It is capped at four characters (uncapped, it resolves typos like `Vendeta` and the typo warning never fires) and tried last. A prefix may not split a number (`sv1` is not `SV19`). Every ordered squeeze is accepted, so the rule never needs to know the official code, and a tie widens. The table `set_aliases` in the registry (D22) maps a code to another hint and is partial on purpose: `MEG` answers to three Mega Evolution groups and ties. Measured against TCGplayer's real lists: 6 of 7 Riftbound codes and 13 of 22 Pokemon codes derive, ties grow with scale, and none resolved to the wrong set. `SP` resolves to `Spiritforged` by the old prefix rule and is left alone, since narrowing it would take `UNL` and `VEN` too.
- **A malformed request gets HTTP 200 with an HTML `System Error` page.** Reading any HTML as a login page sent the operator to re-copy a working cookie, so `tcg_request_rejected` says the session is fine and the defect is here.
- **The capture screen offers the real names.** `GET /tcg/sets` feeds a `datalist`, which suggests and does not restrict, so free text still works and `match_sets` stays. Every failure answers 200 with an empty list and a reason, and the reason is drawn (an expired session names the environment file), because degrading invisibly is wrong. The load follows the field being open, not the row being tapped, since `H` opens it from the key handler.
- **The field says which verdict the typed string gets.** `app/src/setHint.ts` answers `blank`, `unchecked`, `matched`, `ambiguous` or `unmatched`. It judges and never refuses. `unchecked` (no cookie, no network, list not fetched) says it cannot tell instead of accusing a typo. Enter completes a hint that resolved but is not the set's name, and completes nothing that did not resolve. `scripts/set-hint-agreement.py` runs `setHint.ts` under node against `match_sets` over 22 hints and compares whether each resolved and to which set. It is off the commit path because it runs node.

A spawned child sees a rotated key or cookie because `PKMNSCAN_ENV_FROM_FILE` carries the names lifted from the environment file across the spawn, names only and never values.
