## D182 — Slugs stay out of shared index

**Every branch that adds a decision entry was hand-editing two files it shares with every other open branch, and neither edit was ever necessary.** `docs/decisions/ORDER.json` and CLAUDE.md's decision-index block are both fully DERIVED — `scripts/index-decisions.py:normalize` rewrites both, in the same commit, from whatever headings exist right after `make merge`'s claim step substitutes a real number for a branch's slug (D140). A branch's own hand-typed line in either file is discarded the moment its PR merges. What it bought in the meantime was pure collision. Measured the day this landed, **25 of the last 40 merges to main touched `docs/decisions/ORDER.json`**. Every open PR's own manual index line went stale the instant any OTHER PR's slug-carrying entry merged first. Each was computed by hand against an `origin/main` that had already moved underneath it.

**The owner's ruling, on being asked whether to stop committing these files at all**: *"on #1 -- What's the tradeoffs here? It sounds cumbersome so feel free to stop committing them"* / *"Yeah good"*. The literal ask, untracking the files entirely, turned out to be more than the defect needs. It was also riskier than the fix below. `ORDER.json` still has to record where three non-entry sections (Deferred, Someday, the v1 bug table) sit relative to the numbered ones. Nothing but a committed manifest can durably hold that across every worktree in this clone. And CLAUDE.md's index is not a separate generated file at all. It is a rendered section of the project's own instructions file, which is tracked by definition. The tradeoff that actually matches the owner's complaint is narrower and was already half-built: stop the part that never needed doing.

### `docs/decisions/ORDER.json` already didn't need it

`scripts/decisions_corpus.py:order()`'s own docstring said so before this change: *"an unregistered entry is corpus content, not an error"*. A file on disk that the manifest has never heard of is appended automatically, sorted after every numbered entry by `_rank`. Nothing in this codebase ever treated an unregistered entry as a defect (`grep -rn "unregistered\b"` turns up only the two generators that consume it and one commented finding about it). The manifest never required a branch's edit; only the SECOND file did, and a branch copying "how another entry did it" copied both out of habit.

### `CLAUDE.md`'s decision index did need it, and that's the real fix

`check_decision_index` is MECHANICAL and runs on **every commit** — not just `make check`, the pre-commit hook itself (`scripts/githooks/pre-commit` calls `docs-audit.py --staged`, and `check_decision_index` is not conditioned on `staged_only`). Before this change it required exact 1:1 correspondence between every `## D<id> — <title>` heading in the corpus. That included a branch's own still-unclaimed slug heading. It also required a matching line in CLAUDE.md's rendered index. So a branch that wrote its entry file and stopped there failed its very next commit. The finding named its own slug and said the index does not carry it. The pre-commit gate itself was FORCING the hand-edit that caused the churn. (No example slug is spelled here in the two-segment shape a heading would take. A placeholder in that exact shape is a citation. This same file's own extractor would try to resolve it. That is the trap D178's entry records under "It caught its own author twice.")

**The fix exempts only what is genuinely provisional.** `_is_unclaimed(ident)` is true exactly when `ident` matches `_ID_SLUG` (`D` followed by a hyphenated slug, never a bare number) — the same pattern D140 already uses to mean "not yet claimed." `_decision_index_findings` was pulled out of `check_decision_index` as a pure function. That lets `--self-test` drive it without a filesystem. It skips the "has a heading but is not in the index" finding only for an unclaimed id. Every other case this row ever caught is unchanged. A CLAIMED (numeric) entry missing from the index still fails. A stray index line naming no heading still fails. A title mismatch still fails, an out-of-order index still fails, and an empty index is still refused outright.

**A branch's workflow is now: write the entry file, cite the slug wherever code or prose needs to reference it, and touch neither `ORDER.json` nor CLAUDE.md's index block.** The retired claimer's own doc line — *"a branch writes its entry's heading as a two-segment slug, cites it everywhere"* — meant citing the slug in the branch's OWN files. It is unaffected. It never meant hand-editing either shared file, and that reading is what this entry corrects.

### Proved by merge, not only by unit test

The self-test pins six arms directly against `_decision_index_findings` (an unclaimed slug's absence is silent; a claimed number's absence is not; a stray slug in the index with no heading still fires; a title mismatch still fires with a slug elsewhere in the corpus; an empty index is still refused; the exemption predicate itself). Beyond that, this entry's own branch is the proof in production. It was cut after D178. Without ever touching `CLAUDE.md`'s index or `ORDER.json` by hand, it merged `origin/main` past D179. D179 was a different, unrelated PR that DID land a new numbered entry in the interim. It had **zero conflicts in either file**. That is the exact collision this fix exists to remove, reproduced and then not hit.

### What it deliberately does not touch

`check_decision_structure` (heading/bold shape) is untouched — it never required an index line. `docs/decisions/ORDER.json` needed no code change at all. Branches stop hand-editing it. A branch is still free to add its own slug to the index by hand. It may do so if it wants the visibility before merge. The row simply no longer requires it, so doing so is a choice rather than a gate.

### Reopening condition

If a future row grows a requirement that a slug appear somewhere shared before it is claimed, it inherits this same exemption. It does so rather than reinventing the churn. The requirement could be a cross-reference count or a citation graph. `_is_unclaimed` is the one place that judgment lives.
