## D215 — CI runs only reachable browser specs

**`scripts/browser-scope.py specs` maps a change to the specs it can reach, at run time and never from a typed list.** D141 asks whether a change reaches a browser at all. This narrows which spec files a running matrix loads. It fails open in every direction. A gate that quietly narrows is worse than one that does not narrow, since the green is believed either way. Measured over 30 merged PRs, it would narrow 6 of 30. The median saving is 0 specs, so it is a small lever beside the worker count (D136).

- **A spec's reach** is its own relative import closure (`import` and `export ... from`, CSS `@import`, comments stripped). It also includes the closure of every screen whose route hash the spec's body names (matched against `app/src/App.tsx`'s `ROUTES`). It includes every screen when the spec calls `routesFromNav(` (`cursor`, `button-stack`, `copy-budget`, `page-edge` and `wide` sweep the nav).
- **A shared surface selects every spec, not a narrower guess:** `app/src/kit/`, `tokens.css`, `base.css`, `App.tsx` and `App.css`, `main.tsx`, `index.html`, `app/public/`, any non-spec `app/tests/*` file. The config and package files also select every spec (`playwright.config.ts`, `vite.config.ts`, `devPort.ts`, `design-check-reporter.ts`, `package.json`, `package-lock.json`, `tsconfig*.json`). So does anything in D141's top-level `SCOPE` outside `app/` (the Makefile's `design-check` recipe, `check.yml`, `browser-scope.py`, `suite-lock.py`).
- **Every fail-open direction answers every spec and prints its reason:** no merge-base, an unreadable diff, an empty diff (more likely a wrong base), and `BANCHI_BROWSER_SCOPE=off`. A changed path under `app/` that no closure reaches also fails open, since an unmapped file is a gap in the map. So does a path in D141's `SCOPE`. So does a path carrying whitespace, since `make` word-splits `PW_ARGS` and a spaced path would become two filters. Never a block-list: a guessed one let a real Staged import through once.
- **A partial run must not leave a pass record.** D136's `already-passed` job treats an unexpired `design-check-pass-<tree>` artifact as fully tested, so `design-check-passed` in `check.yml` also requires `needs.browser-scope.outputs.partial != 'true'`. Main's push then runs the full matrix for a narrowed tree.
- **Nothing decision-bearing is written.** `specs` only prints and writes `GITHUB_OUTPUT` and `GITHUB_STEP_SUMMARY` (D18). The mechanism is proved by `scripts/browser-scope.py selftest` in `make check` and `make docs-audit`'s `spec map` row (D173). No spec assertion changed, and a full run still loads every case.
- **On the runner,** 20 sequential dispatches after D118's product fix went 0 red of 20. The median matrix took 208.5 seconds, and the maximum 233. Before that, the same case had been red 3 of 20.
