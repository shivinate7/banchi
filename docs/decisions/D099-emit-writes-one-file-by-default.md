## D99 — Emit writes one file by default

**One press writes one import file, `import.csv`, across every run and game named.** Splits are flags, and the cut-off is the store's own configurable `policy.threshold`.

- **The cut-off is standing policy, not a module constant.** It is a property of the operator's hour. So it lives in the corpus beside `rule` and `basis` (D86), with the per-run override shape D180 keeps. `pipeline/pricing.py:THRESHOLD` is only what a store that never set one reads. `SkuMatch.threshold` carries the policy a match was built under. So a report cannot answer `listable` with a figure changed after it was computed. `listable` reads it, and `join_batch` cuts `SubThresholdBucket`'s bands from it. `cli/resolve.py:load` hands it to both `join_batch` and `default_router`. A run routed by one cut-off and partitioned by another disagrees with itself. `pipeline/merge.py:_merged_match` carries the newest leg's, and `_agree_policy` refuses a send whose runs override it differently.
- **It is validated where it is read.** `pricing.check_threshold` returns a `Decimal` or raises `InvalidThreshold`. `Corpus.parse` calls it. So a document that cannot be priced refuses at the read, and not an hour into an `emit`. It is a `ValueError` and not a `MalformedDecisions`. So every `except` naming those two names this one, and `banchi prices show` catches `ValueError`. It does not round: `0.405` is a boundary somebody typed. On the wire it is `policy.threshold`. It is round-tripped by `GET` and `PUT /pricing`, and written even when it is the default. So a control can draw its current value. `GET /pipeline/pricing` reports the stored figure. There is no `--threshold` flag, since a second place to state it can disagree.
- **Splits are flags.** `--split-threshold` writes the old listed and sub-threshold pair under the old names. `--split-games` is the way back if Import to Staged turns a multi-`Product Line` file away, which is not established. A merged file whose games carry different export headers refuses with a sentence naming that flag. `--listed-only` drops the sub-threshold rows and says how many it left. `POST /pipeline/emit` and `POST /pipeline/runs/<name>/emit` accept `listed_only`, `split_games` and `split_threshold` alike. So a screen cannot ask for a split on a send of three and not on a send of one.
- **The merge is not a concatenation.** Inside one run the buckets are disjoint SKU sets (`_game_only` partitions on `listable`), so the cap is spent once. Across runs `pipeline/merge.py` unions positions on `(box, index)` and re-derives the cap: three separate emits wrote two SKUs past a cap of 4, and one merged emit wrote none. One `import_rows` call per game over the union makes a SKU priced once and written once, and `join.write_import` still asserts it.
- **D54's empty guard is per file.** A merged send can now be empty for every game at once. Under `--split-threshold`, an all-above-cut-off send would write a header-only sub-threshold file over a good one. `_warn_stale` globs `import*.csv`, and `_artifacts`' `is_import` tests `import.csv`, which has no hyphen.

Reopen if no operator uses `--split-threshold` (delete the flag and its name helpers), or if Import to Staged refuses a multi-`Product Line` file (`--split-games` becomes the default).
