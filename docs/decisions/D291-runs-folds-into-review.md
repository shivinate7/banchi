**Amended 2026-09-25: the fold is built, and the two open design calls are made.** The review lane moved Runs into a Sheet on Review and made `#/runs` an off-nav redirect. Home's spine went to five stages in the same round. This round builds the rest.

- **The strip's shape.** It is a well, not a warning, because cards that wait to be read are the normal state of a store between runs. It says "Identify N cards, ~$X" and holds two presses (the owner's ruling below).
- **"~$X".** It is this store's own past cost per card: every recorded `usage.cost_usd` divided by every `counts.cards_in` of the same runs, times N (`Runs.tsx:perCardRate`). Both figures are the server's, and no token count is multiplied here. It is not a quote, and nothing is gated on it. The preflight is still the one figure the spend press is confirmed against. The preflight itself was rejected for the strip, because it decodes every waiting photograph (about a minute over 544 cards) and would run on every visit to a daily screen. A store with no recorded spend draws no figure rather than a guess. The run list is read only while cards wait.
- **Past runs.** It is the full list, behind one link: the `history` IconButton on Review's header, which opens the Runs sheet on its run list. This lane chose against a count with the list one press further. The list is the only way to a run's own steps (join, rescue, fetch). A count adds a press and reaches nothing new.
- **One layer above another, in one commit.** The composer and the rescue and live-check sheets moved onto the kit's own Dialog and Sheet (D275). That showed a kit defect. A layer drawn inside another layer, and mounted in the same commit, joined the overlay stack first. React runs a child's layout effects before its parent's. The outer Sheet then painted over the composer and took its clicks, Escape and focus. `kit/overlay.tsx` now hands each layer's panel down to the layers inside it, and a parent that joins late goes under them. Four `run-panel.spec.ts` cases filed as fold regressions traced to this, or to the rescue sheet staying in the DOM while hidden. They run again.

**Amended 2026-09-25, the owner's ruling on the strip: two presses.** The owner's words, verbatim: "i should be able to pick whether i want to wait and get the free pre-check or if i wanna just go right through to the bill". On what "Identify now" does: "Spend immediately".

- **One list, and every half reads it.** The strip's N, its ~$X, the "Identify now" spend and the receipt all come from one list: `POST /pipeline/waiting` (`pipeline_routes.do_pipeline_waiting`). It answers the cards a spend over a selection would buy: each has a photograph, and no live claim holds it (D174). It is free, decodes nothing, and spawns nothing. It is the same two reads the spend route makes before it spawns. So the strip never offers a card the press would be refused. On the demo store, whose captured cards have no photograph, the strip draws nothing. After a spend, the run's claim takes those cards off the list, and the strip stops offering them. `/status`'s `captured` count is only the cheap gate on whether to ask at all.
- **The selection is the composer's opening one, for both presses.** When `#/inventory` handed over ticked cards (`banchi.run-scope`), that set is the selection: the composer opens on its `ticked` start, and the strip names, prices and spends the same set. Otherwise it is every card photographed and not identified. One function derives it (`RunsComposer.tsx:openingSelection`, over `selectionOf`).
- **"Check first"** opens the composer on that selection. Its flow did not change: the free pre-check, then the confirm, then the spend, over D180's selection grammar. A composer opened this way and closed with no run started closes the sheet too, so the operator is back on Review.
- **"Identify now"** starts the paid run at once, with no pre-check and no confirm screen. It spends EXACTLY the strip's list, sent as a `keys` selection (D180, `RunsComposer.tsx:sendOfKeys`) with the composer's default reading. It never sends a state. A card captured in another tab after the strip read its list is not in the list, so it cannot grow the spend. An empty list is refused before the wire. The wire drops an empty `keys` term, and a send with no term buys the whole store. The receipt is a toast with the server's own count (`started[0].cards`), then the run open in the Runs sheet, where its progress reads itself. A refusal is a toast too, so it moves nothing on the screen (D118).
- **The spend route did not change.** It asks only for `confirm: true` (D33), and it holds no pre-check token. D174's claim is still written by the command, inside the transaction that decides which cards it buys. A second tab can never buy the same cards twice. `make submission-selftest` proves that half. The screen adds an in-flight guard, so a double press sends one spend. `review.spec.ts` proves each rule here, and each case goes red on its own mutation: a state sent in place of the keys, the handoff ignored, N read off `/status`, and the guard deleted.
- **What a keys send does not re-check, accepted.** A `keys` send carries no state term. So a card identified between the strip's read and the press is read again, which is usually a free cache hit. And if a capture undo frees an index and a new card takes it, the press buys the new card, at the same count. That is the trade the owner accepted with "Spend immediately". "Check first" still quotes the exact cards before any spend.
- **The demo draws no strip.** The published demo holds no recording of `POST /pipeline/waiting`, so it refuses the read as `demo_not_recorded` (`demoServer.ts`, `docs/specs/demo.md`: an unrecorded read is refused, never answered with an empty list). The strip treats that refusal as nothing waiting, and draws nothing. Identify is frozen in the demo anyway.
- **The estimate says it is one.** "~" marks every figure, "under a cent" included. A title says "An estimate from this store's past runs, not a quote", and a screen reader hears "(estimate)".
- **Which press is worded, and which is primary.** Both keep their words, because both are about money (the iconography rule, step 2). "Identify now" takes the one solid fill, because it is the press that spends and must read as the loud one. "Check first" is ghost. The header itself holds no worded primary, so the header rule still holds.
