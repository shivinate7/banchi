## D167 — Queue entries re-resolve where they stand

**One free, re-runnable command re-resolves every open queue entry against a current export, and a card the operator answers by hand reaches `#/pricing` without a second Join.** Both fix one defect: an artifact frozen at the moment of a join, with nothing in the product able to re-derive it. 513 of 565 stored entries could never see later ladder fixes (`rarity` on candidate rows, D137's Near Mint rule), because `store/queues.py:upsert` is reached only by `queues.apply_run` from `cli/cmd_join.py`, and a join is scoped to a run and a run to a box. An entry whose box holds no live run is frozen at the code that wrote it.

- **`banchi queue refresh` runs the same ladder a join runs.** `cli/requeue.py` composes the `join.IdentifiedCard` as `cli/resolve.py:load` does, hands it to `join.join_batch` with `join.default_router`, and turns the verdict into a `queues.QueueEntry` with `cli/resolve.py:queue_entry`. A refresh that restated the ladder would be the second thing to keep current. When D162 merged mid-branch, the agreement held with no line changed here. It previews by default and writes only with `--write`. The exports default to the ones the joined runs recorded, since the entries need the current ladder and not a newer catalog. `--export` widens what it can find. No quantity arithmetic runs. It writes a question, never a price or a copy.
- **Three refusals come from reusing `queues.apply_run`.** An answered entry is never re-queued or dropped (`cleared_by_human`), so D28's undo stays the only way back out of an answer. `first_seen` survives. A card that has left the box is skipped and not released (D26, D83).
- **Agreement is measured.** Over one run's export the refresh and a real join reached the same verdict on 172 of 172 positions and the same reason and candidate rows on 81 of 81. That measurement found two defects. An empty string is not a number and routes differently (`load` normalizes `(x or "").strip() or None`). A reading must be one reading: `store/master.py:Card.detected_finish` carries the model's fifth field, since an entry may have been written by an older identification of the same photograph. The command is idempotent (a second pass reports 0 changes).
- **Answering the queue folds through to pricing.** D156's `_unsent_ledger` already re-derives every merged row against the live store, and its union now reaches every SKU the store carries for a run on screen. A SKU no table names gets a row composed for it. `pipeline/worklist.py:sku_row` is the one declaration of that twenty-field shape, called by `cli/cmd_join.py:_pricing_table` and by the route, and the extraction was proved inert byte for byte. `claimed_add` is zero on such a row, since no table believes anything about the SKU. This worklist is every copy TCGplayer does not hold (D156), so a committed copy has no row to want. A SKU no export on hand names draws no row, the copies stay counted in `unsent` and `unreachable`, and `Join again` is the door.
- **An answer survives a refresh and undo still works.** `Queue.open_entries` excludes a cleared entry, so the pass never walks an answered position. The fold writes nothing, and `_reverse_answer` restores `card.sku` and `card.condition` from `restores_to`, so the next read simply stops finding the copy.
- **It is reachable on `#/review`** from the page header, as two presses with the preview first (`POST /queues/refresh`, free, `write: false`). The preview is what makes the apply control exist (D87).
- **Not built.** `detected_finish` is `None` on all existing cards, so rung 3's cross-check is absent for them. A backfill was declined, since the newest run record is not always the reading the store holds. A refresh releases an entry the ladder now settles and never re-prices it (D86). It cannot reach a run over a reallocated drawer (D36, D145's `bid`).
- **Guarded but not exercised.** `do_pipeline_worklist` drops a synthesized row when `card.run not in loaded_names`, and deleting that clause changes nothing on real data, so it needs a fixture with two joined runs where only one is loaded. A surviving mutation arm is recorded and not presented as covered. Four more engine paths are unexercised (multi-game catalog, `photo_moved`, the `no_export`, `no_game` and `unjoinable` refusals, `catalogs_from`'s last-file-wins).
