## D236 — Unsold stock is valued by SKU

**Unsold stock is valued by SKU off the price-history archive, one range at a time, and never merged into sold's figure (D225 is the sold-versus-now feature, and each is its own section).** It is a fourth Sales section.

- **The position is the SKU.** Copies are fungible (D212), so a holding is one quantity. `pipeline/holdings.py:on_hand_quantities` counts a copy once, and only when its `state` is not in `store/master.py:TERMINAL_STATES`. It never reads `Listing.live`, a stale marketplace mirror between reconciles. `pipeline/holdings.py:sku_series` reads `store/pricearchive.py:PriceArchive.for_sku` for one range and multiplies each bucket's own `market` by today's on-hand quantity. Quantity is never historical: the store keeps no past counts, so every point is what today's shelf would have been worth on that date, and `SeriesPoint.quantity` says so.
- **Ranges are never merged (D278).** `GET /pipeline/holdings-value?range=month|quarter|semiannual|annual` answers one range per call, `month` by default. The ranges overlap on the calendar, and adding them double-counts.
- **A missing bucket breaks the line, and there are two ways to be missing.** A day the source answered with no price is a stored row with `market: None`, and its point `value` is `None`, never zero. A day no sweep reached is not stored at all, so it cannot carry a null. `gap_before` is a boolean on every `SeriesPoint` after the first, computed from the immediately preceding stored point, and true only when two stored points are not exactly one bucket-width apart. A missing price and a missing day are different facts, and only the second breaks the line by date. `aggregate_totals`' points carry the same field. A screen treats a `null` value as nothing to plot and never draws a line through `gap_before`.
- **The portfolio total is an honest partial sum.** `aggregate_totals` sums, at each calendar start, only the SKUs priced at that exact date, and each `TotalPoint` carries `priced_names` and `unpriced_names`. It never carries a value forward from a SKU this pass did not re-read. A screen never sums `series[].points` into a second total.
- **An unpriced name is counted and never drawn as zero (D277).** `unmarked.names` is the on-hand SKU count minus those `archive.for_sku` answers anything for in any range. A SKU swept under `quarter` and not yet `month` is a coverage fact about the sweep and not an absent card.
- **Sealed stock is a named, countable gap in holdings, and this agrees with D231.** The archive prices sold sealed SKUs, since D231 widened its subjects to the order ledger. Holdings needs an on-hand quantity, and sealed has no `cards` row and never will (`pipeline/games.py`: sealed is never captured), so there is nothing to multiply through. `pipeline/holdings.py:sealed_excluded_count` counts every distinct SKU the order ledger has priced a line for that `cards` has never recorded, without D231's live catalog resolution. The route's `sealed_excluded` carries `names` and a `reason` together, so a caller cannot forward the number without the sentence that makes it honest. Learning about sealed sales adds no on-hand quantity.
- **The wire shape** has `range`, `width_days`, `history_begins`, `at` (an ISO string from `store/master.py:now()`), `on_hand_names`, `series[]` (`sku`, `name`, `quantity`, `latest_value`, and `points[]` with `start`, `market`, `quantity`, `value`, `gap_before`), `totals[]` (`start`, `value`, `priced_names`, `unpriced_names`, `gap_before`), `unmarked.names` and `sealed_excluded` (`names`, `reason`). An unknown range answers 400 `range_unknown`, and an unreadable store 503 `store_unreadable`. A screen never draws `unmarked.names` or `sealed_excluded.names` as zero and never omits either.
- **It is a read.** No route here reads or writes `readings` (D189), and none falls back to it (unlike `do_pipeline_price_now`). `banchi archive sweep` stays the one press that fills the table (D219).
- **`scripts/holdings-selftest.py` proves it against fixtures built in the test** (no store, no network): an on-hand name with no reading counts in `unmarked`, one with a reading gets a correct point, a real calendar gap sets `gap_before` on the point and on the aggregate at the same seam, and a ledger SKU absent from `cards` counts in `sealed_excluded_count`. Two mutation arms (`_adjacent` always true, the sealed subtraction skipped) turn it red. It is not in `make check`, following `scripts/pricearchive-selftest.py`. No coverage number measured on the real store is frozen here, since the next sweep makes it stale.
