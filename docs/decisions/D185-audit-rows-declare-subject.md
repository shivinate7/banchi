## D185 — Every audit row declares its subject count

**A row that examined nothing must say so.** `Report.render` printed `ok` for any empty findings list, so a row that examined 2,964 references and one that examined none were the same word (`paths 0 references resolve`, and a session quoted that run as verification). It is the repo's signature defect: a guard that cannot tell "nothing is wrong" from "nothing is known yet".

- **Every row declares a subject count.** `Report.checks` holds a `Row` NamedTuple carrying `scanned`. The render prints `none` for 0 and `bare` where the row declared nothing. `--json` carries the integer and a `vacuous` flag, since a session greps that instead of reading a hundred rows. Most rows printed a count in prose. They asserted no floor on it. So a moved walk root, a renamed directory or an unreadable corpus all rendered as clean.
- **The `subject counts` row is mechanical.** It has four findings with four repairs. The first is a row that declared no count. The second is an unpinned zero. The third is a `staged` pin whose row is empty in a full run. The fourth is a pin naming a row the file no longer emits. A tag nothing can fail on is what this row ends. A row with findings is not its subject, since the defect is the vacuous `ok`.
- **`EXPECTED_EMPTY` pins rows by name, with the reason and the mode.** Six are `--staged` narrowings that count something out of markdown a code-only commit does not stage. The same zero in a full run is a broken walk, and it still fails. Three are empty on a clean tree in every mode (an empty allowlist, `evidence freshness`, `id claims`). A blanket exemption is how a rule stops being one, so the six doc rows counting a code-side roster are not pinned.
- **A silent `return` deletes its own row from the render,** and an absent row is the state nothing reads. `raw color`, `logo parity`, `lockup bracket`, `rail mark` and `lockup params` emit a row with `scanned=0` now.
- **Eleven published claims got the reader they were cited as having.** `criteria evidence` reads `payload[field]` and compares it numerically with the floor `PASS_CRITERIA` publishes (it once tested only that the string occurred in prose). `check census` reads the token sequence of both `make check` lists. `harness tests` reads every present-tense count in `harness/run.py`'s docstring. `check registry` reads the `ci-check` recipe and `gates: False` against a `NOT A GATE:` marker. `views opsec` matches a render's filename against the route it draws. `storage keys` reads D27's fenced session roster both ways. `server concurrency` reads CLAUDE.md's copy of the four attributed literals. `recorded deletions` has six scan roots, five deletions and thirteen needles. `estimate wire` is anchored on the producing call and never on the wording, or it could not see a reworded sentence. `hatch state` is advisory: it surfaces a standing `BANCHI_*` hatch inherited from an environment nobody typed it into, and `make status` gains a `hatches` line.
- **Two narrowings.** The fifth concurrency fact (the method name that sends `Connection: close`) stays scoped to DEBT11, where the mechanism is argued. `recorded deletions` does not carry D110's three dark-only hover overrides. The cause: a substring needle is either the live class name (red every run) or a string appearing nowhere (a needle that never fires). That needs a CSS-structural reader.
- **Proof.** 44 mutation arms, 0 survivors, each with its legitimate case pinned green beside it. Twenty-eight cases joined `make audit-self-test`. One arm was informative: a row with findings and an empty subject made `subject counts` report a vacuous green, so a findings-bearing row is judged on its findings.
