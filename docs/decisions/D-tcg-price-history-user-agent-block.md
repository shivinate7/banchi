## D-tcg-price-history-user-agent-block — The price history's honest agent stopped answering, and D64's escape hatch already fit it

**A repair, not a redesign. D62 built `pipeline/pricehistory.py`'s reader, its cache, its ranges and its panel; none of that moved.** What moved is one fact D62 measured and printed as true: `pipeline/pricehistory.py`'s own header states, of `infinite-api.tcgplayer.com/price/history/<productId>/detailed?range=<r>`, *"is public. No key, no cookie, no `Referer`, no session — HTTP 200 to a bare `curl`."* — measured 2026-08-30, the day D62 landed. That premise has rotted.

**Measured 2026-09-19, four calls, curl:**

| client | host | result |
|---|---|---|
| this project's own `USER_AGENT` constant, the honest self-identifying default | infinite-api.tcgplayer.com | **403** |
| a browser User-Agent (Chrome 140 on macOS), no `Origin`, no `Referer` | infinite-api.tcgplayer.com | **200** |
| the same `USER_AGENT` default | tcgcsv.com | 200 |
| browser User-Agent | tcgcsv.com | 200 |

No cookie, no `Origin`, no `Referer` changes any of the four. The request signature — specifically the User-Agent — decides `infinite-api`'s answer alone, and it now refuses the same honest string that answered it for D62. `tcgcsv.com` never cared either way and still does not.

**Only `infinite-api` changed.** The catalog walk against `tcgcsv.com` (categories, groups, products, `/prices`) is untouched by this finding — that host answers this project's own default exactly as it always has. The break is narrow: every SKU not already warm in `/.cache` fails its price-history reading (D62's hold-`T` trend panel on `#/pricing`), because a cold read needs the one host that now refuses this client.

**Consequence on `origin/main` before this entry: silent for a cached SKU, a stack trace's worth of confusion for a cold one.** A 403 fell into `Unreachable`, whose only named form on the route is `history_unreachable` — D62's own definition of that code is *"a mirror did not answer, and nothing is wrong with the run."* That is the wrong sentence for a refusal aimed at the client itself, and it is why this sat undetected: cached entries kept answering, so the panel looked alive everywhere it happened to already have been opened.

**The fix reuses `server/tcg_export.py`'s `AGENT_ENV` (`PKMNSCAN_TCG_USER_AGENT`) rather than adding a second knob.** `tcg_export.py` built that escape hatch for exactly this shape of failure — D64: *"AWS WAF sits on `store.tcgplayer.com`... so a block was a plausible outcome this build had to survive."* `.env.example` already documents the key. The key already means "the User-Agent to present to TCGplayer" and nothing about it is specific to the export fetch. `pricehistory.py` talks to a different pair of TCGplayer-adjacent hosts (`infinite-api.tcgplayer.com` and the third-party mirror `tcgcsv.com`), which is the one fact that could have argued for a second key. The measurement above closes that argument rather than opening it: `tcgcsv.com` answers either value, so no host in this walk needs a value the shared key cannot carry. One knob, because there is no case for two different browsers' worth of disguise out of one operator's own `.env`.

**`pipeline/` cannot read `.env` itself.** Its own header is explicit: *"`pipeline/` imports nothing outside itself and the stdlib."* So the value is passed in, not discovered, the same way `Market`'s `cache_dir` already is. `fetch_json` and `Market` take an explicit `user_agent` argument. It defaults to the unchanged, honest string. `server/pipeline_routes.py` resolves the override through `envfile.get_live` — D64's own judgement, because this is a value an operator edits into a running process, and `get` cannot see the replacement — and hands it in at both call sites that construct a `Market`.

**A 403 is now `Blocked`, a sibling of `Unreachable` and never a subclass of it.** `history_unreachable`'s meaning is unchanged and still correct for a timeout, a 5xx, or a host that answers something that is not JSON. A 403 is a different claim: the client is the thing being declined. So it gets its own exception in the module and its own code on the route, `history_blocked`, and that code names `PKMNSCAN_TCG_USER_AGENT` as the remedy. It is a sibling rather than a subclass on purpose: the one place in production code that catches `Unreachable` by name (`server/pipeline_routes.py:_history_for_entry`) now has to catch `Blocked` too, explicitly, so a missed case would be loud — an unhandled exception — rather than a 403 quietly reading as "try again."

**What the honest User-Agent protected, and what protects it now.** D64's argument for an honest, undisguised client was self-identification to a host that was serving this project freely. Its own words: "the operator's own tooling against the operator's own account," with no evidence a disguise was needed. That argument is not reversed here. The default stays the honest string, unconditionally, for every checkout that sets nothing. What is added is an operator's own escape hatch for the day a host stops taking the honest answer. What protects the browser-identifying value itself is the same thing that already protects `TCGPLAYER_STORE_COOKIE`: it lives in the gitignored, hand-edited `.env` and nowhere else. `.env.example` carries the key and a comment naming what it is for. It carries no browser string as a value, committed or otherwise. No message this repair adds prints the User-Agent value in a refusal, a return value, or a log line — only the key's name, so the printed remedy can be acted on without being a leak.

**What would reopen this.** If `infinite-api` or `tcgcsv` ever start blocking on something a User-Agent cannot answer — a fingerprinted TLS handshake, a required cookie, an Origin check — this escape hatch stops working. The honest answer is the one D64 already gave for the export fetch: try again by hand, or accept the read is gone until the host changes its mind. That is a new decision, not a silent workaround of this one.

**Scope, stated so it is not read as wider than it is.** Nothing about what the module fetches, how it caches, how it parses a bucket, or how the two ranges relate has changed. D62's rules on all of that stand exactly as written: the ranges overlap and nothing here concatenates them, the VWAP is the anchor and the bound is a sanity check, direction is a sign and a word and never a color. Nothing here builds a price archive, a ticker screen, or a scheduled fetch. The panel is still a press and nothing here polls it.

**Corrected in the same commit:** `pipeline/pricehistory.py`'s own header, which still asserted the bare-curl claim as though it were still true. `docs/map.py`'s entry for the module, to cite this decision. `.env.example`'s comment on `PKMNSCAN_TCG_USER_AGENT`, which named only the WAF for the export fetch.
