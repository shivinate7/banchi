## D59 — Live count is per SKU

**The live cap is measured against one quantity: what TCGplayer holds for this SKU.** It is never a count of the positions one run happens to see, and each reading carries the time it was taken.

- **One number, two consumers.** `cli/resolve.py:_copies_out` is `min(live + pushed + staged, max(live, pushed + staged - sold))`. `_committed_keys` spends it on positions, so a run knows which copies not to re-send, and `add_to_quantity` subtracts it from the cap. The old code used two different numbers. A SKU split across two boxes had its cap enforced once per box (six rows against a cap of four). A departed copy occupied room forever. `pushed` has no drawdown, so an imported copy was subtracted twice. After a `reconcile`, nothing marked a live copy as held, and 78 duplicate rows across 61 SKUs went back into the file.
- **The floor is the export.** `Total Quantity` is the authority (D8, D11), so the answer is never below it. The ceiling is the sales count, because a copy cannot sell without having been listed. It ages a claim only when the export corroborates a live copy. With `Total Quantity` at zero, a sold card did not leave TCGplayer's hands.
- **The newest reading wins.** `Listing.live_as_of` stamps when `live` was read (the export file's mtime for `join` and `reconcile --live`, `now()` for a D34 release). `Listing.live_reading` is the rule: newer wins, an equal second is the store's, and no stamp on either side is the export's. `observe_live` adopts an export's figure only where the file is newer, and the join report names each SKU it kept with both readings. A stale-high store cannot outrank a fresh-low export.
- **A retired copy still counts as sent.** The card left the box and TCGplayer was never told (D26). So `store/master.py:Inventory.copies_not_sold` filters `SOLD` alone. This is the opposite of `copies_on_hand`.
- **A stuck `pushed` is corrected without a second CSV.** TCGplayer cannot hold more copies than we sent and have not sold. No write and no refusal changes, and D34's release is still the only way to give a commitment up. Clearing `pushed` whenever the export reports the SKU live was refused: `pushed = 4, live = 2` is both "four went live and two sold" and "two landed and two sit in Staged", and those want opposite answers. T7 keeps it as a negative case.
- **The placement is inside the one snapshot and before the write block.** It fixes the join it runs in, and `cmd_emit` re-derives through the same `resolve.load`. A `pushed` zeroed between two write blocks would empty `_stages_held`, which arms `box_not_empty_of_commitments`, `renumber_blocked` and D28's undo refusal.
- **`committed_positions` keeps its job:** keeping a copy out of the sellable set (D54's delta). It no longer answers for the cap. `SkuMatch.nothing_to_add` names the real reason per SKU, because "already at the live cap" was false for an operator who does not reconcile.

It gives up two cases. A hand-listed copy is double-counted, since nothing records which physical card backs a listing the pipeline did not make. A retired copy whose row is in an unimported CSV is counted as sent. No third party can supply a staged quantity, and TCGplayer's own API is closed to new developers, so this stands until it offers one. A marker on `Card`, written by `cmd_emit`'s push loop beside the `sku` stamp, would make the bound exact and is available, not owed.
