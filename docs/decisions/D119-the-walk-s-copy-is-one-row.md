## D119 — The walk's copy is one row

**`#/inventory` draws the copy the walk stands on once, as a row like every other.** The `LocationCard` hero drew it twice, about 150px apart, in two registers, and put emphasis on a copy the UI elsewhere refuses to recommend (`CardLocations.css`: the current row's rail is deliberately not "take this one").

- **`noBar` has no `current` term,** so the current row draws its bar like the rest. `goesTo` keeps it: a walk-to on the row the walk stands on goes nowhere (D45). A `Viewing` pill in the pills cell and a neutral rail mark the row, since they are the only tie between the photograph and a row. The box name is `PositionLabel`'s `boxNote`, as on every row.
- **A card with no SKU and no name is a one-copy list, not a second panel.** `GET /search` refuses an empty query, so such a card is unreachable through it. `Inventory.tsx:loneGroup` builds the group field for field as `do_search`'s loose branch would answer for a bag of one. `listable` stays what the server would send, since the client does not disagree with the store about a number the store computes. A group with no SKU draws no live figure and no `Pushed · Staged · headroom` line, because every one of those is a structural zero. This derives from `sku`, so it also reaches name-but-no-SKU cards. Measured on the store: 1,625 cards, 1,553 with a SKU, 65 with a name and no SKU, 7 with neither. It is a real edge case and not the common screen.
- **The undo lands where the sale was pressed, in the slot D118 reserved.** `.card-locations-action` is reserved at the button pair's own 137x28 so a press cannot resize its slot. The kit's `.bn-receipt` (about 268x36) fits neither way: given a grid row it grew the row from 175px to 213px, and in the action cell it shoves the address. So the row draws the button at the size the buttons already were. The sentence is not lost: the state pill reads `Sold`, and the toast carries `Marked sold.` with the same `Undo`. `primary` survives as a size, exactly the phone's sticky action bar, which has no pill beside it and draws the whole receipt.
- **No balance fix.** The right column loses about 235px flat, and the ragged bottom under a one-copy card is the honest cost of removing content. Shrinking the photograph column is what D32 and D38 spend the pixel budget against.
- **The position-label re-rank is now asserted on the kit sheet** (`app/tests/gallery.spec.ts`), its only renderer since `.inventory-location-label` went. `.kit-poslabel` must set `font-size: var(--pos-slot)` beside `--pos-slot`, or the re-rank's `0.45em` resolves against an inherited 14px and the departed specimen draws like a live one. D41's count of sites is a measurement and is not rewritten.
- **A guard outside the files stops a merge undoing it.** A merge once carried the hero back from a tree that held the pre-deletion files, and every guard the deletion had, sitting beside the component, came back with it. `make docs-audit`'s `recorded deletions` row (`RECORDED_DELETIONS` in `scripts/docs_audit/hygiene.py`) lists symbols a decision records as deleted and checks them against `app/src` on every commit. Adding a row declares a deletion meant to last. Removing one, with the entry amended, undoes it deliberately. It cannot see a re-implementation under another name, which is a design question. A merge resolved against the wrong base is best redone as a three-way merge, not a cherry-pick.

Reopen if the operator wants the address readable at arm's length while standing at the boxes. That is the one thing the hero did that a 22px row does not.
