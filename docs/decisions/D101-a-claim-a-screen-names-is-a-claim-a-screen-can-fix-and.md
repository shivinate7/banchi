## D101 — A banner that names a problem links to its fix

**A banner that names a problem must link to a control that can fix it.** `#/codes` said held codes carry no product claim and sent the operator to `#/inventory`, whose editor had no product field. A reachability rule does not catch a screen that reaches the wrong place. `product` therefore has two doors: the box-level claim editor in `#/inventory`'s Manage box sheet, where every other claim is corrected and one press covers a drawer, and an inline correction on `#/codes` scoped to the lane its banner describes. That is a deliberate narrow exception to the one-door habit. D31 stands: the codes control edits a claim, never a position or a state.

- **A derived tuple outran a hand-written decoder.** `master.CAPTURE_CLAIM_FIELDS` is the authority, `PUT_FIELDS` derives from it and `BOX_CLAIM_FIELDS` from that. When `product` joined, both tuples grew and `do_put_box_claims`' decode table did not. `_reject_unknown` accepted the key and nothing applied it, so the route answered `200` with `"applied": 0, "unchanged": N`, the same sentence it says to a box that already carries the claim. A silent no-op reads as agreement, and no check sent the field.
- **The restatements are reconciled mechanically.** `make docs-audit`'s `claim decode` row AST-reads both decode tables in `server/capture_server.py` and asserts each equals `PUT_FIELDS`. `claim clients` reads `app/src/server.ts`'s payload assignments and `app/src/BoxOps.tsx`'s `ClaimPatch` members against the same tuple. `harness/tests/t7_store_and_seams.py:check_box_claim_product` sends the claim through the box route and asserts the record moved.
- **Not built.** The operator's `note` does not reach the model, because `misc` never joins (`pipeline/games.py`, `catalogued: False`). `cli/cmd_identify.py`'s hand-built `master.Card(...)` is a fourth restatement of the claim vocabulary, and on the create branch it loses `rarity_claim` and `product`.

Reopen for a second game carrying products, or for a third door.
