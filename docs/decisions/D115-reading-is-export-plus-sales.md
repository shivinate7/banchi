## D115 — Reading is the export; later sales beside it

**`live` holds the export's reading and nothing else.** `sold_here` counts copies sold here since that reading, `sold_here_at` dates the newest, and the figure every screen draws is `live_estimate`, the difference floored at zero. `reconcile --live` clears the counter when it adopts a reading taken after the sales, instead of racing it. Marking sold and reconciling can be done in either order and give the same answer.

- **Three writers meant three things.** `Listing.live` was written by `observe_live()` (a reading, dated by the file's mtime), `bump(LIVE, ±1)` (a sale's delta) and `release(budget)` (D34's assertion). "Newer wins" cannot arbitrate a reading against a delta. `bump` also restamped `live_as_of` to `now()`, which forged a fresh reading and let one copy be subtracted twice (92 copies across 56 SKUs read `unexplained`). `bump` refuses `LIVE` outright now.
- **It implements D7's ordering.** D7 wants the screen to agree with the shelf at once, a rule about when the figure drops. The derived estimate drops on the same request and never corrupts the export's reading.
- **The counter needs its own stamp.** The join re-reads a run's recorded export, whose mtime is its fetch time. So an export fetched before a sale and read after it is the ordinary "Join again". Without a stamp it would clear a counter it knows nothing about. `sales_pending` is `live_reading`'s sibling, and both `_copies_out` and `observe_live` use it, so they cannot disagree about one file. It is all-or-nothing, since one stamp cannot split a file that landed between two sales, and the estimate errs low (D7's direction). Its stampless case is the opposite of `live_reading`'s: an undateable file still wins the figure (D8, D11) and cannot cancel a sale.
- **`observe_live` returns a fourth verdict, `CLEARED`,** for a reading that moved no copies and still wrote. The callers would otherwise say something false ("settled N", a zero drawdown, no word for a write the preview promises). The early equality return was narrowed and not moved, so a second `reconcile --live` over one file stays a no-op and does not report itself outranked.
- **Two things read the raw figure on purpose, and the rest read the estimate.** The cap reads the estimate. Once an import has landed and `join` has drawn `staged` to zero, the estimate alone refills a SKU after a sale. It is the only arm of `max(live, claim - sold)` that does so (`check_listing_commands` pins it). The map's key set, the corroboration gate (a fact about the file), and the box-delete guards keep the raw reading. The reason is that a guard on a destructive act takes the safe reading. D34's `release` is untouched and is the only non-export writer of `live_as_of`.
- **No migration.** An absent key defaults to 0 through `Inventory.parse` (D88), and backfilling a non-zero value would be the defect.
- **Both figures are drawn everywhere.** The big figure is the estimate, and `4 when read · 2 sold here since` appears only where something sold. The Fulfiller sees one sentence, "2 copies sold here since we last counted", so the count does not move under him unexplained. Every reading age reads `live_as_of` and not `Listing.at`, which a sale now touches.
- **A frozen run file has no migration, so the reader floors it.** `cli/cmd_join.py` freezes the record into `runs/<n>/pricing.json`, and nothing on that path defaults anything. 171 of 171 records lacked `sold_here`, and the pricing screen drew `NaN live`. `NaN` is silent: it throws nothing and propagates through every subtraction into a word. The reader supplies the zero (`cardState.ts:forSale`, where the arithmetic is, and `Pricing.tsx:LiveCount` had written the expression out). The route may not: a server fill can only be `0`, pairing a stale reading with the store's counter double-counts, and `do_pipeline_pricing` composes only position labels. A type cannot catch this, so `sold_here?: number` says what a record read off disk can promise.

Reopen for a run-file field where absence and zero mean different things, or for an operator who wants an asserted quantity to outrank TCGplayer.
