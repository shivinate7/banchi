## D45 — A copy's label walks to that copy

**A copy's position label in the copies list is the control that walks the box browse to that copy, switching box if it must.** The row is not a button. It already holds `Mark sold` and the retire door, and a button inside a button is invalid markup. The walk-to is a transparent wrapper around `PositionLabel`. It looks the same as a walkable row or a look-only one. Hover and focus are scoped to `.position-slot`. It is absent on the current copy and on a pooled one (D24). It is owner-skin only.

- **`BoxBrowse` takes `goTo: { key, at }`,** the mirror of `onSelect`. The counter lets the same copy be asked twice, and it stops a re-render from replaying an answered request. An imperative ref and a lifted `selected` were both refused.
- **The filter yields to the jump.** Under a query, the follows-the-filter effects move the mark to the first visible row. So a jump to a card the query misses would land on the wrong card, silently. The `sku: null` group is the live case, since it holds only cards that matched themselves. The query is dropped, and the landing re-runs with the whole walk. The jump opens the landing's section itself. The landing effect is declared after both fold effects, so the open is the last word.
- **A shelf change clears the mass-select,** because the selection is box-scoped. A key the walk does not hold does nothing. Reload beside the list is the remedy.
- **The jump scrolls the walk, never the page.** `scrollIntoView` scrolls every scrollable ancestor. On a sticky column it moves the page without moving the row (`window.scrollY` 0 to 280, nav gone). `BoxBrowse.tsx:scrollWithin` adjusts `scrollTop` on each ancestor up to `.browse-map`, then stops. So the document is unreachable by construction, even if the boundary ref is missing. It reads the row's `scroll-margin-top`. It serves every gesture that moves the mark, and `focus()` uses the same route. `scrollWithin` owns where this component scrolls.
- **The guard is a measurement.** `app/tests/inventory.spec.ts` reads `window.scrollY` and the nav's `top` before and after, and requires the landed row in the viewport. Either check alone passes for a wrong reason. The press is dispatched, because Playwright's `.click()` scrolls first and proves nothing.
