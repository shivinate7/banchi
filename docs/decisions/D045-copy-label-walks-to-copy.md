## D45 — A copy's label walks to that copy

**A copy's position label in the copies list is the control that walks the box browse to that copy, switching box if it must.** The row is not a button, because it already holds `Mark sold` and the retire door, and a button inside a button is invalid markup. The walk-to is a transparent wrapper around `PositionLabel`: same pixels for a walkable row and a look-only one, with hover and focus scoped to `.position-slot`. It is absent on the current copy and on a pooled one (D24). It is owner-skin only.

- **`BoxBrowse` takes `goTo: { key, at }`,** the mirror of `onSelect`. The counter lets the same copy be asked twice and stops a re-render replaying an answered request. An imperative ref or a lifted `selected` was refused.
- **The filter yields to the jump.** Under a query the follows-the-filter effects move the mark to the first visible row. So a jump to a card the query misses would land on the wrong card silently. The `sku: null` group is the live case, since it holds only cards that matched themselves. The query is dropped and the landing re-runs with the whole walk. The jump opens the landing's section itself, and the landing effect is declared after both fold effects so the open is the last word.
- **A shelf change clears the mass-select,** because it is box-scoped. A key the walk does not hold does nothing, with Reload beside the list as the remedy.
- **The jump scrolls the walk, never the page.** `scrollIntoView` scrolls every scrollable ancestor, and on a sticky column it moves the page without moving the row (`window.scrollY` 0 to 280, nav gone). `BoxBrowse.tsx:scrollWithin` adjusts `scrollTop` on each ancestor up to `.browse-map` and stops, so the document is unreachable by construction, even with the boundary ref missing. It reads the row's `scroll-margin-top`. It serves every gesture that moves the mark, and `focus()` is the same door. `scrollWithin` owns where this component scrolls.
- **The guard is a measurement.** `app/tests/inventory.spec.ts` reads `window.scrollY` and the nav's `top` before and after, and requires the landed row in the viewport. Either alone passes for a wrong reason. The press is dispatched, because Playwright's `.click()` scrolls first and proves nothing.
