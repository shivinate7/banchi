## D128 — Attach the key listener before paint

**A key press answers to what is on the screen, so a window `keydown` listener is registered in `useLayoutEffect`, never `useEffect`.** A passive effect runs after the browser paints. For one task the screen shows the new state while the attached listener is the previous render's. A press in that task is answered by the wrong render. The sheet closes mid-request, or Escape finds no field to close. A layout effect runs inside the synchronous commit, before paint, so no test evaluation or human input can interleave. `app/src/runsOverlay.ts:useOverlayFocus` (`hold`) and `app/src/CaptureScreen.tsx`'s field handler (`openField`, and `fieldPick` closes over it) both register this way.

- **It is a product fix.** `useOverlayFocus`'s hold exists so a stray Escape cannot close a sheet whose request would then toast for a sheet that is gone (D87, D100). The failing window opens the moment the request starts, when a person is most likely to press Escape. A retry in the spec would make the test true and leave that.
- **The evidence was one defect, reproduced on demand.** The CI runner uses one worker (Playwright's default under `CI`), and about one run in five lost one test, always at the assertion after a `keyboard.press('Escape')`. `Emulation.setCPUThrottlingRate` at 10x with four cases five times each failed 3 of 20 before the fix and passed 20 of 20 after. It was not runner starvation, and failure did not track wall-clock.
- **Refused, each would have hidden the count:** `retries: 1` on CI (reclassifies as flaky, and every casualty would have been retried past the defect). A longer `expect` timeout (the Escape was lost, not slow). A worker change (there is one). A retry loop around the Escape in the spec. The `F` retry in `capture-claims.spec.ts` stays, since its cause is a different window: no listener on first mount before the first passive effect.

It does not touch D122's lock (two fleets on one Mac), does not change what the suite asserts, and does not promise a green CI.
