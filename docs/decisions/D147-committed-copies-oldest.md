## D147 — Committed copies are the oldest captures

**When the store says TCGplayer holds N copies of a SKU, the N positions that stand for them are the N oldest captures. They are never in box-walk order.** `cli/resolve.py:_committed_keys` turns a per-SKU quantity into a set of positions. It picked with `copies_on_hand(sku)[:out]`, which is box-walk order. The docstring said any N would do. That is true of `len()` and false of the set subtraction. `SkuMatch.uncommitted_positions` subtracts those keys from one run's positions, so which copies are chosen decides which run may list. D7's fungibility is about physical cardboard and says nothing about which run may send one.

- **Causality is the ordering.** A copy captured after the last emit cannot be among the copies that emit sent, because `cli/cmd_emit.py` walks the run's own positions. A run covers one sitting. The store cannot name the copy that backs a listing, so this is an inference, and the only one causality permits. A copy with no `captured_at` sorts oldest. That is the conservative direction (withheld, not sent). On a store with no stamps, the function equals the old box-walk slice, since `(box, index)` breaks the tie.
- **Box-walk order stranded real cards.** With backstock in box 3 and tonight's capture in box 1, the copies photographed an hour ago were marked as already live. The older backstock, which no run joins, was reachable by nobody. On a 322-card run, rows written went from 196 to 241 and SKUs adding nothing from 52 to 7 (59 stranded cards).
- **`Inventory.copies_on_hand` keeps box-walk order.** `pipeline/orders.py` hands that list to the fulfiller, and the box walk is the order a hand moves through a drawer. The ordering is local to the one caller that needs the other question. `Listing.at` is a touch stamp written by every writer, so it cannot stand in for a push time.
- **Refused: preferring copies outside the run being emitted.** It makes the committed set depend on which run is emitting, so two runs holding one SKU each exclude themselves. That is a global quantity answered by a run-scoped view, D59's defect exactly (83 copies across 61 SKUs offered past what exists).
- **It is not D7's send quantity.** With no quantity typed, `SkuMatch.asked` is `None` and `add_to_quantity` returns `room` unchanged. What was wrong was which positions `uncommitted_positions` had left. A stuck claim that no ordering reaches is D150's.

Reopen for a marker that a copy actually reached an import file (D59). The marker is one field on `Card`, written by `cmd_emit`'s push loop beside the `sku` stamp. Then the committed set is read and this ordering is a fallback. Also reopen for a run over more than one box (D180), whose guarding fixture would need one run spanning two sittings.
