## D171 — Refusals must reach a reader

**A refusal nobody reads did not happen, and a status line the session wrote is not a reading.** Two shapes of one class, a reader that cannot tell "nothing is wrong" from "nothing is known yet". A commit refused by `scripts/githooks/pre-commit` had its output sent to `/dev/null`. The session then read `git log --oneline -1`, saw the previous commit, and reported "pushed", and the empty push read as success. A merge driver's printed `GREEN` was relayed as progress while two racing instances merged nothing.

A rule to check one's work is a rule a session can defer to, and it was deferred to by the session that wrote it. What cannot be deferred to is a command that will not run and a report the session did not write. So the first shape became a refused command, and the second a generated report.

- **`scripts/silent-write-guard.py --hook` (PreToolUse on Bash): a git write must leave a trace the session can read.** A write whose stdout or stderr goes to `/dev/null`, a closed descriptor, or a file the same command never reads back is refused. Stdout carries the proof and stderr the refusal. The predicate is an invariant, not a roster of spellings (`>>/dev/null`, `&>` and `2>&-` all count). Descriptors are walked in order, as the shell does. The tokenizer is `shlex` with `punctuation_chars`, never a regex, since a quoted `>/dev/null` in a commit message is a string. Heredoc bodies are cut and the rest kept. The verb roster is short, because each verb is false-positive surface: `commit`, `push`, `pull`, `merge`, `rebase`, `cherry-pick`, a `fetch` carrying a local refspec, `make merge` and `gh pr merge`. `git add`, `tag`, `reset`, `checkout` and `revert` are absent. A verb goes in when something has gone wrong through it. `git fetch origin main:main` and `git -C <tree> pull --ff-only` are in because CLAUDE.md tells a session to type them, and a silenced `reference-transaction` refusal leaves main where it was. A bare `git fetch origin -q` is a read. Claude Code does not run this copy, on the owner's word: the shared layer's silent-write rule owns that side, and `.codex/hooks.json` keeps this script.
- **False positives are pinned as passing** and each is run in the fixture: an exit-code test (`git rev-parse -q --verify MERGE_HEAD >/dev/null 2>&1`), a read (`git fetch origin -q 2>/dev/null`), an unwind (`git merge --abort`), a dry run, `git merge-tree` and `git merge-base`, the retired merge self-test (the goal match is exact), a quoted redirect, output kept and read (`2>&1 | tail -40`), a file read back, and a multi-line script whose `>/dev/null` belongs to an `echo` (`shlex.whitespace_split` treats a newline as whitespace and would otherwise disable the guard the first afternoon). A guard with a false positive is switched off. A broken guard fails open (any parse error or malformed payload exits 0). `PKMNSCAN_SILENT=off` is the escape hatch and is printed in every refusal.
- **A status report is generated, never quoted from a tool's stdout.** Every figure is read from the repository and GitHub at the moment it is run. A verdict is pinned to a HEAD SHA (`commits/<headRefOid>/check-runs`). A commit short of the floor is `not ready`, since every reported check passing is what the incident read as green. The floor is a set of required names read from `branches/main/protection` (`check`, `revert-guard`), never a count: main's tip includes push-only `build` and `deploy`, and PRs path-gate the browser matrix. A required context that is missing or `skipped` is `not ready`. `conclusion: null` is `running` and never `failed`. `check-suites` is unusable (a permanently queued suite from the `claude` app). Liveness comes from the console app's per-session records with the start time checked (`scripts/janitor.py:_same_process`), since pids were recycled within minutes, and never from an mtime. A block it cannot read prints `UNKNOWN` with the reason and exits non-zero. Group processes by absolute path, since four `serve.py` instances is correct under D43. Its generator, `scripts/coordinator.py`, has since been retired, and the rules stand for any status report.
- **`make silent-write-selftest` gates and is not in the git hook** (D18: it writes a temp repository). It reproduces the incident first with a throwaway repo whose pre-commit hook refuses, and it scores the refusal's own text. Two surviving mutation arms are defense in depth, and two more had no case that needed them, so cases were added.

The guard cannot know that a session read the output it was forced to keep. It removes the ability to discard a refusal, and it sees one command at a time. A heredoc never terminated drops the rest of the command, which fails open. A user-facing refusal names the setting to change in plain words (D196), and the variable name stays in the docs and logs.
