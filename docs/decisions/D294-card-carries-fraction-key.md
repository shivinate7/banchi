## D294 — Each card carries a fraction order key

**A card's place is an order key apart from its stored index.** `Card.order` is a number beside `Card.index`, in the payload and in the real column `cards.ord`. The walk, every label and every section bound read it. The stored index never moves (D10, D58).

- **The key is a fraction and it starts at the index.** A gapped integer (the index times 1,024) would rewrite every divider and section name's key. As a fraction, nothing moves when it lands. The schema 13 migration (`store/db.py:_add_card_order`) gives every card the key its index already is. So every box reads in today's order, every label counts as before and every stored divider is already a key. A capture into an untouched box takes its own index, so that box stays the identity (`BoxOrder.identity` is the fast path). An insert writes only the cards that move. A card placed between two others takes `lo + (hi - lo) * n / (count + 1)`. One gap halves 20 times before two keys come closer than `KEY_EPSILON` (one millionth). Then the box is re-spaced once (`Inventory._respace`, logged `box_respaced`). That is the one write that touches cards a placement did not move.
- **A divider is a key.** A section starts at the first card whose key is at or above it. The first divider is the front of the box (1, or below 1 after a placement in front of card 1). A divider past the last card is a plan counted in whole slots (`Position._divider`). Section names are keyed by `divider_key`, which is `31` for every divider stored before the order key.
- **`Inventory.place` is the one placement.** It takes the arrivals in order (dividers and cards) and a gap: in front of a section, at the near end, in front of a card, or at a section's end. Only the arriving cards take new keys. A card that crosses boxes leaves a tombstone with `moved_to` (D83), and the tombstone keeps its key. A mid-box delete (D10 ruling 1) slides the indices and writes no key: the deleted card leaves a gap in key space that nothing counts. Sliding a key equal to its index crossed the keys of placed cards. The delete also points each tombstone's `moved_to` at the card's new index, so the join can still follow it.
- **Single cards and ranges use the same write.** `POST /boxes/<box>/cards/move` (`do_move_range`) takes one card or a range from a lifted section on the Shelf. The route drops it in front of any card or at the end of any section. It has the same receipt shape and undo. No divider moves with a card. A card placed in front of a section's first card joins that section, so its divider moves down to it. The other routes are `POST /boxes/<box>/sections/move` and `POST /boxes/sections/undo`. The store half is `Card.order`, `BoxOrder`, `Inventory.layout_of`, `Inventory.place`, `Inventory.drop_sections` and `_respace`. T7's `t7_box_map.py` covers the migration, the keys after each kind of move and the card and range moves.
- **Undo reads the data and never a clock** (`docs/specs/undo.md` section 2). A move writes one `sections_moved` event. It holds both boxes' dividers and names as they were. It also holds every card's old key and old state, and a hash of each box after the move. Undo compares the hashes. While neither box has changed it puts every card, key, divider and name back exactly. Anything that wrote to either box since refuses, and the way back is a new move.
- **The divider editor speaks card numbers and the store keeps keys.** A start the operator did not change keeps the divider already stored, so a save never moves one it was not asked to. An edited start maps to the key of the card at that number, never `int()` of it. An empty section is kept: a card move can leave one, its divider is still in the box, and an unchanged save keeps it with its name. The editor draws it with the start of the section after it, and that repeat is taken as the empty section and not refused. Dropping it is the operator's act, by removing that start.

Not built: the public demo answers no move, since its stub server has no handler for the three routes. A save can move a divider past departed records, since the editor's number then maps to the first card on hand (low severity).
