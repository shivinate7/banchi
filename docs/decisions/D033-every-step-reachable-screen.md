## D33 — Every pipeline step is reachable from a screen

**The four pipeline commands are reachable from a screen. Exactly one route can spend money.** This is the largest instance of `CLAUDE.md`'s route-is-not-a-feature rule in this repo. The owner asked how to push runs at box or section level from the app, get data back and manage CSVs. A session designed the screen and drew a mockup, without building it. The owner then asked why no promised UI existed. Both were correct. `./banchi identify | join | emit | reconcile` had existed since build-order step 4. It had run a 53-card run and a 544-card run. Only a person typing at a terminal could reach it.

**`server/pipeline_routes.py` is its own module.** It is the one part of the server that can cause money to be spent. `server/capture_server.py`'s header promised that this process never spends money. It holds no API key and makes no outbound call. Both halves stay literally true. Nothing there reads a key or opens a socket to Anthropic. The old sentence was rewritten rather than leaned on. A promise that quietly narrows to a technicality is the drift D16 exists to catch.

What replaces it, because a guarantee deleted and not replaced is a regression:

- **One route spends, and is named for it:** `POST /pipeline/identify`. It refuses without an explicit `confirm` field. It refuses a second run over a capture directory that a live run is already reading. A double-click is the realistic accident. Two live batches over one box are two invoices for one answer.
- **The preflight is free, is a separate route, and creates no run directory.** `identify --dry-run` returns before `runs.create`. The screen must show it first.
- **Everything else is free and re-runnable.** That is the property D1 gave the two-phase split.

**The money step spawns and is never awaited. Every other step runs in the request.** That is the shape of the work, not a preference. A batch takes minutes to hours, and no HTTP request may be held open for that. `join`, `emit` and `reconcile` are local arithmetic over a parsed CSV. The child is detached and logs into the run directory. So **a run outlives the server that started it.** The Mac sleeps, `make server` restarts, or a tab closes. The poll still reads the run directory. `cli/runs.py` already makes a run an immutable input rather than state. This design leans on that entirely, and nothing is held between requests.

**Amended: a handle on each child is held between requests.** The last clause above was wrong. `start_new_session` is `setsid`. It creates a new session, not a new parent. So a detached child is still a child of the capture server. Nothing called `.wait()` or `.poll()` on it, and there is no `SIGCHLD` handler. An unwaited child that exits becomes a zombie that holds its pid. **`os.kill(<zombie>, 0)` succeeds.** That is the whole defect. `_live_pid` decided liveness by signal 0 alone, over a `running.pid` file that nothing deletes. So a finished run kept reporting `live`. Measured on the owner's `box4-04` run, a run that finished in 3m52s drew `Running 8m` and kept counting. `_busy_run` refused that box for a new identify the whole time. It corrected itself only after this process constructed another `Popen`. CPython reaps `subprocess._active` inside `Popen.__init__`. A server restart also corrected it.

**What is held is a handle, and it is deliberately not an answer about a run.** `_CHILDREN` maps a run directory to the `Popen` of the child this process spawned. `poll()` is both the question and the reap. Without a handle, the answer must come from the files, never from "not running". So a restarted server holds none, and it reads every run exactly as before. The promise above is intact. A run still outlives this server.

The three answers are ordered. A handle that says running wins outright. A handle that says exited ends the run. Only with no handle at all do the files decide. The order closes a race that the manifest would otherwise lose. `cli/cmd_identify.py` writes `collected=True` before the record, and before a whole locked store write over every card. On a 544-card run, that write takes seconds. A rule that let the files demote a running child would put `Needs join` on screen while identify was still writing. With no handle, the floor is the run's own `identifications.json`. That file is written atomically, and the next step reads it. `collected` is not the floor, because it stays true through the whole tail. The janitor ruling (claude-settings decision "The janitor is one machine-wide sweep") already holds that liveness is read, not guessed. This applies that rule to a process instead of a session.

**Amended: the receipt carries the actual figure, not only the estimate.** The gate puts the estimate in front of the operator before they spend. Nothing told them what the send cost. The Identify step drew `290,470 tokens in · 3,761 out` beside a hardcoded `Costs money` pill. That pill warned about a decision the screen does not offer, since a run directory exists only once the spend route has spawned a child. The console in the same card said `estimated cost $0.14`. **The run cost $0.1546.** Now `identify/cost.py` is the only place in the repo that multiplies a token count by a rate. `cli/cmd_identify.py` records `cost_usd` into the manifest at collect time. That makes true a claim that `cli/runs.py` and `docs/specs/batch-script.md` had both been making. For runs that predate the field, the server fills the figure in at read. It says so on the wire. Without that, the fix would be invisible on every existing run. The pill now reads `Spending now` in flight, `Cost $0.15` after, and `Costs money` only on runs that were never submitted.

**Scope is a box, or a selection inside one.** A subset becomes a directory of symlinks, built **outside `captures/cards/`**. That placement is load-bearing. `identify.sidecar.scan` walks its root recursively. A scope directory under it would be walked by the next run pointed at the box above, and every card would be submitted twice. The scope directory is gitignored under the opsec rule as well as the derived one. A bearer instrument reached through a symlink is still a bearer instrument.

**Exports are uploaded, never named by path.** A screen cannot know what is on the server's disk. A route that opened any absolute path a request named would be a file-read primitive. An origin header would be its only guard. Uploading also leaves the run holding the exact bytes it was joined against. The manifest could describe those only by hash.

**The money gate is two steps, and it takes no typing.** This is the owner's ruling. The operator checks the cost. They read the count and the estimate the command printed. Then they press the confirm that appears beneath them. The confirm does not exist before the preflight has answered. It is absent, not disabled. A disabled button is one attribute away from pressable, and a later refactor drops that attribute without noticing. `docs/DESIGN.md` permits a gate on a genuinely destructive action. The cheapest honest gate here makes the number impossible not to have seen.

### Placement

The panel sat on `#/inventory` until it got a route of its own. D39 records where that argument was overruled and how. The reasoning here still holds, and D39 was built against it. D31 collapsed three screens into that route, because they were separate instances of one thing. A run is not a different thing again. It is something done to the box being walked, or to the cards just ticked in it. A route of its own would re-implement the box strip, the search and the mass-select. It would then be free to disagree with them about what is selected.

D39 splits it. The box is re-answered by a picker of its own, which is cheap and cannot disagree with anything. The selection is not re-answered. `#/inventory` keeps the one mass-select in the product, and hands the ticked indices over. So there is still exactly one place a selection can be made. Read the paragraph above as the specification that build had to satisfy. Do not read it as a placement this file still asserts.

**Nothing folds, and `BoxOps` does not fold either.** This entry once read "folded by default", on `BoxOps`' measured reason. The panel was about 250px, reached once a box, on a screen whose question is where is this card. The owner overruled the fold. They ruled that the box and the run both stay open, with no click-in, and the buttons drawn. The argument for the fold had the weaker half of a true premise. Reaching the panel once a box is the primary task, not an exception to it. NN/g prices a collapsed panel at five accumulating substeps (scroll, scan, decide, target, wait) before the first click of real work. This repo's own record makes a related point. Three routes shipped with full T7 coverage and no reachable control at all, which is where the route-is-not-a-feature rule came from. A control behind a fold is one step better than that, but it is not a different kind of thing.

**The space comes from the column, not from a disclosure.** It has been moved three times. The third placement is the panel's own measure. The column is gone, since its height had set the grid row that positioned the card's copies (D38, amended). So the panel moved to the last row of the content column and gets the full width. At 1024px it draws 625px closed and 1143px open. A 370px track gave 799 and 1461. No code changed to get that. The head stops wrapping four command names, and the step notes and free steps unwrap with it. Nothing folds, nothing is capped, and nothing scrolls internally. Every control this entry protects is still drawn unconditionally. What moved is the reading order. `app/tests/run-panel.spec.ts` asserts that as an absence: `<details>` and `<summary>` at zero inside the panel. That is the one form of this ruling that no future relocation can falsify.

The two earlier placements are kept, because the sequence is the argument. `BoxOps` and the run panel first shared one grid row beneath the card detail (`.browse-boxrun`, `1fr 1fr`). That paired them into one panel's height, not two. The `defaultOpen` prop, the two disclosure triangles, their `[open]` flips and both `-webkit` marker resets were deleted then, and they stay deleted. Then the two panels stood in a third column of their own, to the right of the card. The owner asked for that. It is the same argument at its limit. The row cost the card's column one panel's height. The column costs it nothing. The space came from the card's own photograph, shrunk to the height of the fact rows beside it (see D38). Stacked in that column, `BoxOps` sits above the run panel. `.browse-boxrun` is a flex column rather than a grid, so shelves with no box panel produce no leading gap.

### All four steps are on screen in every state

Three of the four steps were not on screen in every state before a fix. `RunPanel.tsx`'s `STEPS` list is authored, not derived from `phase`, and its own comment says why. A screen that only drew the current step would hide emit until join had finished. The promise was kept against `phase` but broken against `detail`. Join, emit and reconcile rendered inside the open-run guard. So with no run picked, the panel drew Identify and nothing else. With no runs at all, the pipeline's other three quarters existed nowhere in the document. A first-time operator could not learn the pipeline had four parts until after they had paid for one. `app/tests/run-panel.spec.ts` showed the gap in its own body. It had to click a run row before it could assert the four titles.

The heads and the notes now always draw. The controls stay behind a picked run, **absent rather than disabled**. That is the discipline the money gate already keeps, for the reason `.run-button`'s comment gives. One sentence above the three says which state the operator is in.

**Three defects were fixed alongside, and all were reachable before.** `stepOut`, `decisions` and `decisionsBad` were never cleared after the open run changed. So run A's answer rendered under run B. `saveDecisions` posts the textarea to whatever `openRun` is at the moment of the press. It could write A's edited `decisions.json` into B. A step's answer now renders inside the step that produced it. It is matched on the step the click requested, never on the server's echo. The spec mocks all three routes and returns `step: 'join'` for every one. That was harmless only because the answer rendered unconditionally.

The run list is also re-read on a timer: every 4s while anything is live, and every 20s otherwise. A run started in a terminal begins live. A poll gated on live runs could never find the case this route exists for. A live run shows how long it has been running, from its own `created_at`. `identify/batch.py` logs only on a status change. So a console tail written forty minutes ago looks the same as a hang. Elapsed time is measured, not estimated. There is no per-card signal on the wire, so no progress bar is invented.

**Every command's stdout is shown verbatim, and nothing summarizes it.** That is `docs/DESIGN.md`'s copy rule for the owner's screens. The one thing the panel adds is the download link for a file the console can only name. That is the gap `docs/GATES.md` records as what Gate B did not close. Emit's import files existed only as filenames. The owner never sees that output, because someone else drives the commands.

**`decisions.json` is edited as text, not as a form.** The route says in its own comment that it does not validate what a disposition means. `emit` owns that refusal. A typed form would encode the schema a second time in TypeScript, where nothing audits it against `pipeline/decisions.py`. The file already explains itself. `join` writes a `_note` block that names every field and what `emit` will refuse without.

**`--force-resubmit` is deliberately not offered to a screen.** It is the one identify flag whose purpose is to pay again for an answer already bought. D32's known cache gap means that a re-crop cannot be told apart from a re-run by the cache. It stays a terminal flag until the crop becomes part of the cache identity.
