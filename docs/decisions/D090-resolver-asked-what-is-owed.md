## D90 — The resolver is asked what is owed

**`Ledger.outstanding` is the quantity that reaches the engine (`_engine_order`), never `line.quantity` raw.** A line of 3 with one copy pulled wants 2. The raw quantity resolved a partly filled line as if nothing had been pulled. With five copies in the store it allocated 3 picks against a line owed 2. That is not a local error. `resolve_all` is a one-pass allocation over the whole open set, and its double-book guard is D69's most important property. A surplus pick takes a copy out of the pool every other order for that SKU draws from, so a second buyer's line reads `short` over a copy the first is not owed. `pipeline/orders.py:OrderLine` accepts quantity zero and refuses only negatives, so a filled line resolves as `resolved` with its breakdown still counted. On the wire a resolved line carries `owed` (the ledger's figure) beside `wanted` (the buyer's).

A slot is never stored beside a capture id (D36). A `{box, index}` in the ledger is a second address for a card, and it goes stale the first time a card in front of it leaves the box (D10, D58), with no `photo_sha256` to re-bind by. Composed per read it is true. `_order_progress` composes no position at all now, since a recorded copy has left the box.

Copies are fungible (D7, D212). A copy's box never decides whether it can fill an order. The allocation refuses a copy another line already targets, not the drawer. A hand-swap that could undo `resolve_all` would put D69's double-book defect back.

The envelope press this entry once built, `POST /orders/fill` recording every copy of an order on one press, was deleted (D97). The route name now belongs to D113's different capability. If a whole-order write is ever rebuilt, keep the reason it had: N calls to a per-SKU route leave a half-recorded envelope that one undo cannot reverse (`pull_spans_lines`). A whole-order write is one transaction, one refusal that names the line and position with nothing written, and one undo. `_prepare_targets` and `_ledger_pull` remain the shared phase-one code for `POST /orders/pull`.
