# D90 — The resolver is asked what is owed

**`Ledger.outstanding` is the quantity that reaches the engine (`_engine_order`). The raw `line.quantity` never does.** A line of 3 with one copy pulled wants 2. The raw quantity resolved a partly filled line as if nothing had been pulled. With five copies in the store, it allocated 3 picks against a line owed 2. The error is not local. `resolve_all` is a one-pass allocation over the whole open set, and its double-book guard is D69's most important property. A surplus pick takes a copy out of the pool that every other order for that SKU draws from. So a second buyer's line reads `short` over a copy the first buyer is not owed. `pipeline/orders.py:OrderLine` accepts quantity zero and refuses only negatives. So a filled line resolves as `resolved`, with its breakdown still counted. On the wire, a resolved line carries `owed` (the ledger's figure) beside `wanted` (the buyer's).

A slot is never stored beside a capture id (D36). A `{box, index}` in the ledger is a second address for a card. It goes stale the first time a card in front of it leaves the box (D10, D58), and no `photo_sha256` exists to re-bind it. Composed per read, it is true. `_order_progress` composes no position at all now, because a recorded copy has left the box.

Copies are fungible (D7, D212). A copy's box never decides whether it can fill an order. The allocation refuses a copy another line already targets, not the drawer. A hand-swap that could undo `resolve_all` would bring back D69's double-book defect.

The envelope press this entry once built was deleted (D97). It was `POST /orders/fill`, which recorded every copy of an order on one press. The route name now belongs to D113's different capability. If a whole-order write is rebuilt, keep the reason it existed. N calls to a per-SKU route leave a half-recorded envelope that one undo cannot reverse (`pull_spans_lines`). A whole-order write is one transaction. One refusal names the line and position and writes nothing. It is undone by one undo. `_prepare_targets` and `_ledger_pull` remain the shared phase-one code for `POST /orders/pull`.
