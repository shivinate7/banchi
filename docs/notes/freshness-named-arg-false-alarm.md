- freshness-named-arg-false-alarm: On `origin/lane/orders-reread` (PR 1137, not on main), recogniser 14 finds a registered re-read only when the `useRereadOnWrite` argument is an inline function that reaches a read (`reachesRead` walks calls inside the argument). `useRereadOnWrite(reread)` with a named function matches nothing, so the write is flagged though the screen re-reads. The helper match also needs the write inside the `afterWrite` call's own argument, so `afterWrite(save)` with a named `save` is flagged the same way. It bites when a re-reading screen is reported stale, which teaches readers to skip the report.
